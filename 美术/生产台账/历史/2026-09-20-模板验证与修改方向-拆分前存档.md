# 3D角色＋2D场景美术模板验证与修改方向

> 状态：执行基线（模板验证阶段）；旧完整3D场景规范已退役，本文件是当前唯一美术依据
> 日期：2026-09-20
> 用途：记录新美术方向、首件模板的建立方法、验证步骤和量产前门禁
> 技术方向：Mutable角色＋Motion Matching Loco＋2D分层场景＋插画对白
> 当前执行：跳过Blender灰盒验证，直接以分层PSD母版推进；Blender仅作为后续可选辅助
> 基线规则：模板批准前只改本文件、不改量产资产；批准后改任何变量先走 §19 五步

## 1. 本文件解决什么

本文件不定义正式地图，也不沿用旧地图构图。它只回答以下问题：

1. 项目所说的“真正美术模板画面”由什么组成。
2. 如何用Photoshop和UE制作并验证该模板（Blender仅作可选辅助，见 §6）。
3. 3D角色、2D场景、作物、动物与对白立绘怎样共享一套视觉语言。
4. 哪些项目通过后才允许批量生产。
5. 后续修改美术方向时，应修改哪些变量，而不是推翻全部资产。

本文件独立自包含，不依赖其他文档。旧地图、旧六场景列表、旧完整3D场景路线已退役，不作为生产依据；历史内容只看git，不在本文件追溯。

## 2. 方向定义

### 2.1 一句话目标

固定斜俯视镜头下，正常比例的风格化3D角色行走在分层手绘2D世界中：画面有中式日常生活气、柔和设色与清晰的玩法可读性，角色、场景、对白立绘看起来属于同一作品。

### 2.2 技术边界

- 主角和NPC：3D骨骼角色，使用统一人体骨架和Mutable部件系统。
- 角色移动：Motion Matching Loco（须先通过 §28 前置Spike，否则降级BlendSpace／状态机）；劳动、交互和剧情动作使用Montage或独立动作层。
- 世界场景：2D纹理置于3D空间，优先使用Masked Static Mesh Cards承载。
- Paper2D：主要用于需要逐帧播放的作物、动物和局部特效，不承担整个场景的唯一组织方式。
- 碰撞：视觉面片与碰撞代理分离；角色坐标不为排序而修改高度。
- 对白：独立2D插画肖像，不依赖3D脸部表情。
- 地图：先用无剧情含义的验证庭院确立模板，正式地图后续另行设计。

### 2.3 风格关键词

- 中式日常，不堆砌宫殿、宫灯和符号化“古风”。
- 温暖、柔和、安静，但保留少量冷色和雾气形成层次。
- 水彩、淡彩厚涂或有色线稿均可使用，但必须统一轮廓强度和细节密度。
- 角色为正常比例风格化人物，不使用临时Q版精灵作为比例模板。
- 地面安静、交互物清楚、远景柔和，不能所有区域都同样抢眼。

## 3. 什么才算“真正美术模板画面”

真正模板不是单独一张概念图，也不是单独一个角色转台。它是一组在同一版本下制作、能够互相校验的画面与源文件。

### 3.1 必须交付的三张主画面

#### A. 游戏主画面模板

在UE实际镜头中同框包含：

- 一名最终比例候选的3D角色；
- 一块可行走地面；
- 一段道路或地表边界；
- 一栋建筑的墙角、门和前檐；
- 一棵拆分树干与树冠的代表树；
- 一种作物的幼苗与成熟阶段；
- 一个可交互道具；
- 一处角色从物体前方走到后方的遮挡关系；
- 脚底接触阴影；
- 最小玩法提示，例如目标格或交互提示。

该画面用于确认角色比例、轮廓、透视、接地、色彩、笔触、遮挡与玩法可读性。

#### B. 时段与季节模板

使用与A完全相同的相机和摆放，至少输出：

- 中性白天；
- 黄昏或夜晚；
- 一个季节变化候选，例如秋季或冬季。

该画面用于确认变化来自可维护的材质参数、遮罩和替换层，而不是仅依赖全屏滤镜。

#### C. 对白界面模板

同一角色输出：

- 3D世界中的角色截图；
- 中立对白立绘；
- 开心、悲伤或生气中的两种表情；
- 实际对话框、姓名、正文与选项按钮；
- 16:9正常画幅和至少一个较窄画幅检查。

该画面用于确认立绘与3D角色的发型、肤色、服装语言和年龄感一致。

### 3.2 必须附带的拆解页

模板画面之外，需有一张拆解页标注：

- 相机参数；
- 角色身高与屏幕像素高度；
- 每个2D层的世界位置；
- Pivot与接地点；
- 碰撞代理；
- 前景遮挡层；
- 纹理尺寸与实际显示尺寸；
- 日夜、季节和湿润等遮罩；
- 资产名称和版本；
- 未解决问题。

没有拆解页的漂亮截图不能作为生产模板。

## 5. 首件验证场地

### 5.1 验证庭院

首件不使用正式农场、小镇或山区地图，避免地图方向变化导致返工。建立一个无剧情含义的约14m×8m验证庭院：

```text
远景山体／天空
────────────────────
代表树      建筑墙角＋门

道路／草地        交互道具

作物测试区    角色移动与遮挡路线
────────────────────
前景树冠／矮墙遮挡
```

该庭院只测试：

- 角色行走；
- 建筑和树的比例；
- 场景前后层次；
- 角色接地；
- 作物状态；
- 日夜和季节变化；
- 对话触发后的界面统一。

### 5.2 相机候选基线

在最终相机批准前，以以下数值作为第一轮比较起点，而不是永久锁定值：

- 固定斜俯视；
- Pitch约40°；
- 正交投影；
- Ortho Width约1400cm；
- 16:9，1920×1080输出；
- 禁止自由旋转；
- 如保留缩放，应额外测试最近、标准和最远三个档位。
- 庭院14m×8m与Ortho Width 1400cm按16:9配套设计；改一边必须同步改另一边，并重出A画面。

正交与小FOV透视若仍需比较，必须在角色屏幕高度一致的情况下比较，不能只复制相机距离。

## 6. 当前直接PSD路线与Blender边界

当前模板不建立Blender灰盒，先在1920×1080分层PSD中直接确定构图、角色比例、场景线条、细节密度、日夜与季节候选。PSD画面通过后，再把批准的相机和资产边界带回UE验证。

Blender保留为可选辅助，只在以下情况使用：

- 复杂建筑的透视容易画错；
- 同一建筑需要多个受控方向；
- 需要Normal、Depth、Object ID、Emission Mask或Shadow Mask；
- 需要批量预渲染树木、道具或可复用结构；
- 需要确认3D角色与建筑入口、工具或家具的真实尺度。

使用Blender时仍需固定相机角度和焦距，输出透明无损RGBA（PNG或TGA），并保留Blend源文件、相机和渲染预设。预渲染结果必须进入Photoshop统一轮廓、笔触、色块、细节频率和边缘软硬，不能直接作为最终画面。

固定镜头下不默认生产多个角度。只有玩家能旋转或同一资产确实需要多朝向时，才制作2向、4向或更多方向。

### 7.2 绘制顺序

1. 先用灰度确定角色、道路、建筑入口和交互物的视觉层级。
2. 再确定冷暖和饱和度，不先堆纹理。
3. 先完成大色块和轮廓，再增加中等结构，最后只在焦点区域增加小细节。
4. 把地面细节压低，保证角色、成熟作物和入口优先可读。
5. 关闭纸纹、LUT和雾层后复查，底层资产仍应属于同一风格。
6. 将批准的画面分解回可生产资产，不直接把完整截图切成地图。

### 7.3 细节分配

建议以70／25／5控制细节：

- 70%大色块与安静区域；
- 25%结构、材质和中等笔触；
- 5%高对比焦点与故事细节。

地面不能遍布同强度的草叶、碎石和线条。玩家可交互目标附近的纹理对比应更低，目标物自身对比应更高。

## 8. 2D场景资产分类

| 类型 | 例子 | 核心规则 |
|---|---|---|
| 远景板 | 天空、山、远村、海 | 少量大图，弱对比，可做视差，不承担碰撞 |
| 地表基底 | 草地、泥地、石地 | 使用可拼接Patch，不画死完整地图 |
| 地表边界 | 道路边、田埂、溪岸 | 与基底分离，便于改布局 |
| 状态层 | 翻耕、浇水、积雪、泥泞 | 由数据驱动，不写入基础地面 |
| 建筑主体 | 房屋、商店、亭台 | 主体、屋顶或前檐、入口和碰撞分开 |
| 植被 | 树干、树冠、灌木、花簇 | 接地部分与遮挡部分分开 |
| 普通道具 | 箱、井、摊位、石头 | 底部中心Pivot，记录交互点和碰撞 |
| 动态资产 | 作物、动物、水、旗帜 | 使用Flipbook资源或材质动画（Flipbook可直接作Cards材质帧源，不等于用Paper2D组件），不绑死在场景图中 |
| 前景遮挡 | 树冠、屋檐、桥洞、矮墙 | 写入深度或使用受控排序，可淡出但不关闭必要碰撞 |

## 9. 世界纹理和导出合同

### 9.1 源文件

- 绘制资产保留PSD、KRA或等价分层源。
- 预渲染资产保留Blend源、相机、灯光和渲染预设。
- 原始参考、AI辅助记录、授权和人工修改范围随资产卡保存。
- JPEG仅作为预览，不作为正式世界纹理Master。

### 9.2 导出

- 透明资产使用无损RGBA和Straight Alpha。
- 透明边缘进行颜色扩展，防止Mip产生黑边或白边。
- 图集单元之间预留8至16像素扩边。
- 世界纹理保留Mip；是否使用图集按资产更新频率和材质批次决定。
- sRGB只用于颜色纹理；Normal、Mask和数据纹理使用线性色彩空间。
- 源图统一正向保存，垂直翻转由固定导入或UV规则处理，不能每张图临时决定。

### 9.3 像素密度候选

若标准镜头宽约14m、输出宽1920像素，则屏幕密度约为137px/m。第一轮Master建议按不低于180至200px/m准备，并通过Mip在引擎内降采样。Master总量必须通过 §29 纹理池预算；超预算先降远景与地面密度，不降角色与交互物。

该值只用于首件：

- 最终像素密度必须结合最近缩放档确认；
- 大地面必须切成可流送Patch（尺寸与接缝规则见 §26），不能制作一张超大完整地图；
- 远景可低于该密度；
- 角色脸、对白立绘和UI不使用世界px/m规则。

## 10. 空间、Pivot和遮挡合同

### 10.1 Pivot

- 建筑、树、道具：Pivot位于底部接地点或规格指定的拼装点。
- 作物：Pivot位于根部中心，所有生长阶段保持一致。
- 动物：Pivot位于双脚或身体投影中心，所有动作帧保持一致。
- 前景树冠：Pivot与树干装配点一致，不能靠目测偏移。

### 10.2 排序

- 角色保留真实世界坐标和高度。
- 不根据屏幕Y值动态改变角色世界Z坐标。
- Masked材质优先写入Depth，让真实空间关系处理遮挡。
- 只有必须半透明的内容才使用Translucent排序。
- 建筑前檐、屋顶和树冠必须拆成可独立控制的遮挡组件。

### 10.3 碰撞与交互

- 视觉面片不自动等于碰撞。
- 建筑墙体、树干、桥面和边界使用独立简单碰撞代理。
- 门、床、箱、井和作物有明确交互锚点；锚点数据格式与读取接口见 §31。
- 隐藏或淡出前景视觉时，不得一起关闭必要碰撞和交互。

## 11. 3D角色与2D环境融合

### 11.1 角色材质

- 使用高粗糙度、克制高光和柔和明暗。
- 皮肤、布料、头发的高光宽度不同，但不能出现写实塑料质感。
- 如使用轮廓线，以实际1080p画面中的像素粗细验收，不按模型单位固定宽度。
- 角色最暗部分不应比场景线稿黑出一个风格层级。

### 11.2 推荐首轮光照基线

- 2D环境使用Unlit光照模型＋Masked混合模式（以下简称Unlit-Masked）：颜色稳定且写入深度；只有必须半透明的内容才用Translucent。
- 3D角色使用独立可控的主光、环境填充和轮廓光。
- 脚底使用风格化接触阴影、投影贴花或专用接收方案。
- 白天、黄昏、夜晚通过材质参数、局部遮罩和角色灯光共同变化。
- 全屏LUT只做最终统一，不承担窗户亮灯、积雪、湿润和植被换季。

### 11.3 同框检查

必须在角色：

- 面向镜头；
- 背对镜头；
- 建筑前后；
- 树冠下；
- 道路与草地交界；
- 白天和夜晚；

分别截图检查。单个角色转台好看不能替代同框验收。

## 12. Mutable角色生产方向

### 12.1 部件槽位

```text
Body／Head
Hair
UpperBody
LowerBody
Shoes
Hands
AccessoryHead
AccessoryNeck
AccessoryWaist
AccessoryBack
```

OutfitPreset只保存组合配方，不代替独立槽位参数。

### 12.2 必须建立的矩阵

- 部件与骨架版本；
- 服装隐藏哪些身体区域；
- 发型与帽子兼容性；
- 上衣与下装腰部兼容性；
- 鞋与裤脚兼容性；
- 各部件LOD对应关系；
- 材质槽和UV规则；
- 极限动作穿插结果；
- 合法与非法参数组合。

复制身体蒙皮权重不等于不会穿模。服装必须结合身体裁切、留量和最坏动作测试。

### 12.3 NPC分级

| 等级 | 建议数量 | 角色美术 | 对白立绘 |
|---|---:|---|---|
| 主角 | 1 | 完整Mutable换装和捏脸范围 | 6至8种核心表情，解决换装同步 |
| 核心NPC | 约6至8 | 独立头脸、发型、轮廓与标志服饰 | 6至8种表情，可有专属姿势 |
| 重要NPC | 总数约20 | 人工指定Mutable配方，至少一个独有轮廓特征 | 4种核心表情，按剧情增加 |
| 普通NPC | 10至20 | 共用部件库，但由美术指定组合 | 1张中立，必要时增加1张反应 |
| 路人 | 后续按需 | 才允许受控随机 | 默认无完整表情包 |

重要NPC不得由运行时随机组合直接生成正式身份。

## 13. 对白立绘模板

### 13.1 画布和构图

- 先按最终UI实际显示尺寸确定Master，不使用“统一1024以上”作为唯一标准。
- 建议保留2048级分层Master，再按UI导出适合尺寸。
- 所有人物统一眼线高度、头顶安全区、肩线范围和光线方向。
- 表情切换时头部、眼睛和肩膀不能跳位。
- 普通文本不得烘在图片内。

### 13.2 表情集合

通用核心表情为：

- Neutral；
- Happy；
- Concerned或Sad；
- Angry；
- Surprised；
- 角色专属表情按剧情增加。

不是每名NPC都必须机械生产同样数量。重要程度和剧情实际用量决定最终集合。

### 13.3 主角换装同步

主角必须在以下方案中选择一种并固定：

1. 立绘只展示头肩，尽量减少服装变化区域；
2. 帽子、外套和配饰使用立绘叠加层；
3. 对白固定使用身份肖像，不承诺反映当前穿着。

未选择前，不批量制作主角换装立绘。

## 14. 作物与动物

### 14.1 作物

生长阶段与动画帧分开：

```text
CropID
  StageID
    VisualAsset
    OptionalIdleAnimation
    RandomVariant
    Pivot
    Footprint
    SeasonVariant
    HarvestReadability
```

- 所有阶段根部Pivot一致。
- 成熟阶段在正常镜头下无需文字也应可辨认。
- 同阶段可提供2至3个轻微随机变体，减少整齐复制感。
- 风动优先考虑材质或少量循环帧，不为每个阶段制作无必要的大型帧表。

### 14.2 动物

动物不能只写“Idle、Walk、Eat、Sleep”而忽略方向。至少定义：

- 需要4向还是8向；
- 哪些方向允许镜像；
- 每种状态的帧数和帧率；
- 转向、受击、互动和睡眠切换；
- 脚底Pivot与接触阴影；
- 与前景和角色的深度关系。

## 15. 日夜、季节和天气

### 15.1 日夜

至少拆分：

- 全局时段色；
- 角色灯光；
- 窗户、灯笼和炉火Emission；
- 天空与远景替换或渐变；
- 地面湿润与反光参数；
- 夜间交互物可读性补偿。

### 15.2 季节

季节不是四个LUT。至少评估：

- 植被叶色或叶片替换；
- 地面覆盖变化；
- 花期和落叶；
- 冬季积雪边缘；
- 作物可用季节；
- 建筑和道具上的局部覆盖。

### 15.3 天气

- 雨雪可由Niagara表现，但地面和角色仍需湿润、积雪或色调反馈。
- 粒子不能遮挡目标格、作物成熟状态和对话UI。
- 前景雨雪、世界粒子和远景雾分别控制，避免整屏同一速度和尺度。

## 16. 美术模板验收表

### 16.1 硬门禁

以下任一项失败，模板不得进入量产：

- 相机参数未记录或仍频繁变化；
- 角色与建筑比例不可信；
- 3D角色明显像贴在2D背景上；
- 地面、建筑和树的透视不一致；
- 角色经过树或建筑时遮挡错误；
- 角色脚底漂浮或阴影方向错误；
- 交互物和成熟作物在正常画面不可读；
- 夜晚只能靠整体压暗；
- 季节只能靠全屏换色；
- 源文件无法重建或只有最终PNG；
- 地面画死正式地图布局；
- 需要依靠未记录的手工导入操作才能正确显示。
- Masked边缘在目标抗锯齿方案下出现不可接受的闪烁或噪点；
- 某批次DoD（含 §27 看板验收）未关闭就进入下一批。

### 16.2 评分项

每项按0至2分记录：0不通过，1需修改，2通过。

| 项目 | 检查重点 |
|---|---|
| 轮廓 | 角色、入口、树、作物第一眼可读 |
| 比例 | 人、门、工具、作物和道路相互可信 |
| 透视 | 所有2D资产共享相机逻辑 |
| 色彩 | 冷暖、饱和度和明度层级统一 |
| 线条 | 角色材质与场景线稿不冲突 |
| 细节 | 地面安静，焦点区域有控制地丰富 |
| 接地 | 脚底、建筑、树和作物不漂浮 |
| 遮挡 | 前后关系稳定，不靠移动角色高度修正 |
| 动态 | 日夜、季节、湿润和作物状态成立 |
| UI | 对话立绘与世界角色身份一致 |

| 可维护 | 源文件、参数、命名和重导入流程完整 |

硬门禁全部通过，且评分项无0分，才允许批准模板。1分项必须列出负责人和关闭日期。

## 23. 术语表

- Card／面片：承载2D纹理的Static Mesh；Layer／层：PSD或场景中的逻辑分层；两者不是一回事。
- Flipbook：Paper2D逐帧资源；可作Cards材质帧源，不等于用Paper2D组件搭场景。
- Patch：可拼接、可流送的地表块；Master：可重新导出的最高质量源（PSD／Blend／2048立绘）。
- 首件：第一个按模板生产的可运行资产；模板：A／B／C三画面＋拆解页＋§18冻结项；母版：PSD风格源。
- MM：Motion Matching locomotion；Mutable CO：可定制对象资产；配方：部件＋参数组合存档。

## 24. 命名规范

### 24.1 通用

- 只用ASCII；版本后缀_v001起；批准后改名必须在 §33 记录映射。

### 24.2 源文件（美术资产／下）

- PSD：`LookDev_<场景>_v002.psd`；切片：`<AssetID>_<部位>_v001.png`（如`HouseA_Wall_v001.png`）。
- 角色源：`<CharID>_<Part>_v001.blend`或`.fbx`。

### 24.3 UE内资产

- 2D纹理`T_MR_2D_<Asset>[_<部位>]`；Cards网格`SM_MR_2D_<Asset>`；2D材质`M_MR_2D_<用途>`，实例`MI_…`；Flipbook `FB_MR_<Asset>_<动作>`。
- 角色：骨架`SKEL_MR_Human_Base`（已锁定v1）；网格`SK_MR_<Char>_<Part>`；Mutable CO `CO_MR_<Char>`；动画蓝图`ABP_MR_<Char>`；MM数据库`MM_MR_<Char>_<版本>`。
- 材质参数前缀：`G_`全局时段、`S_`状态（湿／雪）、`E_`自发光。

### 24.4 Master与运行纹理

- Master无engine后缀；运行纹理由目录区分（§25），不靠改名区分。
