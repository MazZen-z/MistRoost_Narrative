# 3D角色与动画管线

> 编号：ART-STD-004 · 版本：1.2 · 更新：2026-09-24 · Owner：角色美术（会签：TA、动画、程序）
> 类型：**流程规范**。角色、动物与场景同为 3D；角色要和手绘贴图的场景看起来是同一幅画。
> 前置：[相机与空间合同](01-相机与空间合同.md)。
> 冻结等级：**冻结项 2/8**。

---

## 1. 这条管线要解决的唯一难题

> **让角色看起来和场景是同一幅画，而不是一个写实模型走进了插画里。**

所有规范都服务于这一条。角色单独渲染好看**不算通过**，必须同框验收。

---

## 2. 技术边界

- 主角与 NPC：3D 骨骼角色，**统一人体骨架** + **Mutable 部件系统**。
- 移动：**Motion Matching Loco**（须先通过 §7 前置 Spike，否则降级 BlendSpace / 状态机）。
- 劳动、交互、剧情动作：Montage 或独立动作层。
- 对白：**独立 2D 插画肖像**，不依赖 3D 脸部表情（见 [立绘与UI管线](04-立绘与UI资产管线.md)）。

---

## 3. 角色与环境的融合规范

### 3.1 角色材质

- 高粗糙度、**克制高光**、柔和明暗；贴图画法与环境一致（参照主角四件道具）。
- 皮肤 / 布料 / 头发高光宽度不同，但**不得出现写实塑料质感**。
- 若用轮廓线：以**实际 1080p 画面的像素粗细**验收，**不按模型单位固定宽度**（透视下远近粗细不同）。
- 角色最暗部分**不应比环境暗部黑出一个风格层级**——这是"贴上去"的最主要来源。

### 3.2 光照基线

| 对象 | 方案 |
|---|---|
| 环境 | 实时灯光（太阳 + 天光 + 雾岚），手绘贴图承载画意（[3D场景管线 §5–§7](02-3D场景资产管线.md)） |
| 角色 | **与环境共用同一套灯光**；可读性不足时，用只作用于角色的光照通道补一盏柔和补光 |
| 脚底 | 实时阴影；必要时加柔和接地贴花 |
| 日夜变化 | 灯光随时段 + 材质参数；角色补光与环境同步变化 |

角色与环境共享灯光，夜晚不会再出现"环境变了角色没变"；补光只为可读性，**不另立一套与环境矛盾的光向**。

### 3.3 接地

- 接地靠实时阴影；需要加强时用柔和的接地贴花，方向与太阳一致。
- **始终保持一个可信的主光方向**，不允许逐件自由发挥。

### 3.4 同框检查（硬性，6 种情况都要截图）

角色 **面向镜头** / **背对镜头** / **建筑前后** / **树冠下** / **道路与草地交界** / **白天与夜晚**。

> 单个角色转台好看**不能**替代同框验收。这是本管线最常见的自欺方式。

## 4. Mutable 部件系统

### 4.1 槽位

```text
Body／Head
Hair
UpperBody
LowerBody
Shoes
Hands
AccessoryHead
AccessoryNeck
AccessoryWaist
AccessoryBack
```

`OutfitPreset` 只保存**组合配方**，不代替独立槽位参数。

### 4.2 必须建立的兼容矩阵

复制身体蒙皮权重 **不等于** 不会穿模。以下九项必须逐项建表并验证：

1. 部件 ↔ 骨架版本
2. 服装隐藏哪些身体区域
3. 发型 ↔ 帽子兼容性
4. 上衣 ↔ 下装腰部兼容性
5. 鞋 ↔ 裤脚兼容性
6. 各部件 LOD 对应关系
7. 材质槽与 UV 规则
8. **极限动作**穿插结果
9. 合法 / 非法参数组合

服装必须结合**身体裁切 + 留量 + 最坏动作测试**三者，缺一不可。

### 4.3 已锁定

- 人体骨架 **`SKEL_MR_Human_Base` v1**：玩家与 NPC 共用。
- **改骨架 = 新版本 + 全部件重验**，没有例外。

## 5. NPC 分级

| 等级 | 建议数量 | 角色美术 | 对白立绘 |
|---|---:|---|---|
| 主角 | 1 | 完整 Mutable 换装与捏脸范围 | 6–8 种核心表情，解决换装同步 |
| 核心 NPC | 6–8 | 独立头脸、发型、轮廓与标志服饰 | 6–8 种表情，可有专属姿势 |
| 重要 NPC | 总数约 20 | **人工指定** Mutable 配方，至少一个独有轮廓特征 | 4 种核心表情，按剧情增加 |
| 普通 NPC | 10–20 | 共用部件库，但由**美术指定**组合 | 1 张中立，必要时 1 张反应 |
| 路人 | 后续按需 | 才允许受控随机 | 默认无完整表情包 |

> **重要 NPC 不得由运行时随机组合直接生成正式身份。** 一个有名字、有台词、会被玩家记住的角色，必须有人为它拍板长相。

## 6. 动画规范

- 动作分层：Locomotion（MM 或降级方案） / 劳动与交互（Montage） / 剧情（独立层）。
- **固定镜头意味着侧面和背面永远会被看到**，不允许只为正面调动作。
- 工具动作必须与场景交互锚点对齐（挥锄、浇水、采集的落点）。
- 帧率与压缩预设统一登记在资产卡；重导入必须可复现。

### 6.1 当前接入状态（2026-09-21）

| 项 | 值 |
|---|---|
| 玩家动画蓝图 | `/Game/MistRoost/Characters/Player/ABP_Chr_Player` |
| 目标骨架 | `/Game/MistRoost/Characters/Base/SKEL_MR_Human_Base` |
| 来源 | 由 `/Game/Characters/Mannequins/Anims/Unarmed/ABP_Unarmed`（GASP 第三方）复制后改写，**GASP 原件未动** |
| AnimGraph | 仍是模板原样：Locomotion 状态机（Idle / Walk-Run 混合空间）+ Jump / Fall Loop / Land |
| EventGraph | **已全部重写为 Mover 取数**（见下） |

### 6.2 动画蓝图不许 Cast 角色类（硬规则）

本项目角色继承 **APawn + Mover**，**不是 ACharacter**，身上没有 `CharacterMovementComponent`。

> 引擎模板动画蓝图（`ABP_Unarmed` 等）的写法是 `Cast<ACharacter>` → 读 `CharacterMovementComponent`。
> 这个 Cast 在本项目**必然失败**，失败后 GroundSpeed 恒为 0、角色只播 Idle，**而且一条错误都不报**。
> 2026-09-21 就是这个坑：`BP_Chr_Player` 当时指着 `ABP_MannyExtended`，
> 它的 TargetSkeleton 是插件里的 `SK_Mannequin`，与 `SKEL_MR_Human_Base` 不匹配，
> 骨架不匹配时 UE 直接不运行 AnimInstance，同样不报错——表现为参考姿势（A-Pose）。

所以动画蓝图一律**直接向 Mover 组件取数**，不要 Cast 角色类：

| 动画变量 | 取数来源（`UMistCharacterMoverComponent`） |
|---|---|
| `GroundSpeed` | `GetGroundSpeed()` |
| `ShouldMove` | `ShouldPlayMoveAnimation()`（有速度**且**有输入意图） |
| `Direction` | `GetMoveDirectionAngle()` |
| `IsFalling` | `IsFalling()`（Mover 基类自带） |

取法：`TryGetPawnOwner` → `GetComponentByClass(MistCharacterMoverComponent)` → 上面四个函数。
`GetComponentByClass` 的 `ComponentClass` 引脚填对后输出引脚会自动定型，**不需要再加 Cast 节点**。

**两条排查提示**（都属于"不报错但不动"）：

1. 角色是 A-Pose → 先查 AnimClass 的 **TargetSkeleton 是否等于网格的骨架**。
2. 角色站着播 Idle 但不迈腿 → 查 EventGraph 是不是还在 Cast 角色类。

## 7. 首件门禁

### 7.1 Motion Matching 前置 Spike（V04 开工前必须完成）

用现有动画源跑通：固定镜头下**移动、转向、启停**；记录动画分钟数、调参项、CPU 开销。

**通过标准**：动作不断裂、不滑步（或滑步可接受且已记录）、调参路径明确。
**不通过则降级**：BlendSpace / 状态机。V04 改验降级方案，并更新 §2 与台账。

### 7.2 Mutable 首件验证（V04 内）

CO 手工搭建后必须验证：

- 部件切换（上下装、发型至少各一件）
- 形态滑杆最小链路
- 合成后材质正确
- 换装不丢 LOD / 物理
- **CO 烹饪打包通过**

### 7.3 V04 必须同时关闭的合同项

| 项 | 为什么卡在这 |
|---|---|
| 角色最终身高 | 决定 [相机合同 §3、§6](01-相机与空间合同.md) 的屏幕高度与门洞、交互高度 |
| 角色 LookDev 基线 | 决定材质、轮廓线、光照三者的档位 |
| 立绘换装方案三选一 | 见 [立绘与UI管线](04-立绘与UI资产管线.md) |

## 8. 常见错误速查

| 症状 | 原因 | 对策 |
|---|---|---|
| 角色像写实模型走进插画 | 角色暗部过黑 / 高光过硬 / 贴图画法与环境不一致 | §3.1 |
| 夜晚角色和场景脱节 | 角色补光没跟随时段 | §3.2 补光与环境同步 |
| 轮廓线远近粗细不一 | 按模型单位设线宽 | §3.1 按 1080p 像素验收 |
| 换装后穿模 | 只复制了蒙皮权重 | §4.2 三件套：裁切＋留量＋最坏动作 |
| 角色脚下漂浮 | 阴影被关或接地贴花缺失 | §3.3 |
| NPC 长得都一样 | 用了运行时随机 | §5 重要 NPC 必须人工指定 |

## 9. AI 概念 → Blender 装配 → AccuRIG → 项目共用角色（本轮建立）

这是主角优先、随后用一名普通 NPC 验证复用的制作流程。文字流程已建立，**不代表任一角色已经完成这些步骤**。主角提示词与 NPC 模板见 [角色提示词块](../../../美术资产/_提示词块/04-角色_v001.md)；设计意图见 [角色设定](../设计方向/03-角色与立绘设定.md)。

### 9.1 先后顺序与交接

| 阶段 | 工作与产物 | 本阶段通过才进行下一步 |
|---|---|---|
| 选外观 | 用户生图，我做对比审看与提示词迭代；选定一张完整主角母图 | 脸、发型、大色块、衣装构造成立；记录选定图 |
| 补结构 | 从母图补正面 A-Pose、侧面、背面及局部图 | 同一人、同尺度、同拼色方位；后背补设计得到确认 |
| 基础人体 | 确定完整人体、头脸与手足；保持身体表面可供服装套合 | 人体比例、关节位置、颈／腕／踝接口可靠；不能用多次独立生成的人体片段直接拼凑 |
| 分部件成形 | 围绕同一人体制作头发、上衣、裤、鞋、配饰 | 图像不是网格；生成模型需检查开口、厚度、隐藏结构和姿态，重新整形不合理处 |
| Blender 装配 | 统一单位、朝向、落地、比例和姿势，清理网格，准备 UV／材质 | 见 §9.2；交付可重开源文件及绑定输入导出 |
| AccuRIG 初绑 | 用户完成关节点定位、身体／手部绑定及动作预览 | 肩肘、髋膝、手指、脚踝动作可用；保存初绑工程、导出设置与 FBX |
| 共用骨架对齐 | 对照现有 SKEL_MR_Human_Base v1 的实际骨架核对并完成适配 | 见 §9.3；不能用改名代替骨架兼容，也不能直接覆盖项目骨架 |
| 角色材质与 UE 首件 | 回到实际镜头与环境，接现有角色动画／换装链 | §3.4 同框检查、§4.2 兼容矩阵、§7 首件要求分别通过 |
| NPC 复用 | 先选体型接近主角的一名普通 NPC，替换头发、衣装和配色 | 沿用同一流程而非重新造一套骨架；通过后再扩展体型与年龄 |

概念设计和网格准备可先做；进入 V04 动画整合仍遵守 §7.1 的前置要求。AccuRIG 绑定成功不替代 Mutable、动作或实机验收。

### 9.2 Blender 装配清单

- 以完整人体作为共同参照。工作文件可保持独立对象；“拼装”不等于把衣服、头发和皮肤焊成一个连续网格。
- 身体本身要连续可靠；日后若独立头、手、脚，切口位置、对应顶点、法线和权重需专门建立合同。首件不默认拆人体四肢。
- 单位必须能往返验证，导入 UE 后检查真实厘米高度；不要仅凭 Blender 的显示单位认定尺寸正确。最终身高仍由 V04 决定。
- 参考姿势围绕统一基础人体建立；A-Pose 或 T-Pose 是结构与初绑输入，最终必须与目标骨架参考姿势协调。服装沿同一姿势制作。
- 检查孤立碎片、重复面、错误法线、自相交、破洞、过薄或封死的衣口。服装开口与分离对象本身不是错误，不做无差别“封所有洞”。
- 对肩、肘、裆、膝、踝和手指保留适合弯曲的拓扑；自动减面不能替代关节拓扑。高质量生成表面也可能需要局部或整体重拓扑。
- 贴图以固有色及受控绘画层次为主；不要把背景、地面阴影、强方向轮廓光烘进人物 BaseColor。保留原图与原始网格，工作修订写新目标。
- 根据 §4 的槽位准备拆件、身体隐藏区、UV 与材质；独立对象并不要求每件独立一套大纹理。面数／骨骼预算只引用 [性能合同 §2](06-性能预算与技术合同.md)，本节不另设数字。
- 导出前保存源工程；把导出重新导入独立检查场景，核对高度、法线、贴图路径、对象和姿势。只是按了导出按钮不算通过。

### 9.3 AccuRIG 与共用骨架之间不能省略的步骤

官方建议以 A-Pose／T-Pose 等合适姿态输入；绑定后的角色可导出 FBX，并选择目标应用。参见 [推荐模型姿态](https://manual.reallusion.com/ActorCore-AccuRIG-1/Content/ENU/1.0/04-Load-Character/Recommended-Modle-Types.htm) 与 [AccuRIG 2 导出说明](https://manual.reallusion.com/AccuRig-2/2.0/09-add-motions/export.htm)（2026-09-22 查阅；本机版本与实际选项仍需核对）。

**以下是本项目的适配要求，不是声称 AccuRIG 自动提供这些结果：**

1. 提取现有目标骨架的骨名、父子关系、参考变换、根节点、单位与轴向，与首个 AccuRIG 输出逐项比较。不能因导出预设写着 Unreal 就认定它等于项目骨架。
2. 可先保留 AccuRIG 输出为中间角色验证变形；正式共享部件必须绑定到经核对的项目骨架。需要时在 Blender 将网格姿势、蒙皮权重与目标骨架适配后重新检查。
3. **重定向动画只解决动作映射，不会自动把网格换绑到另一副骨架**。不能以重定向能播放替代同骨架部件测试。
4. 不让每件衣服各跑一次自动绑定再声称它们共用骨架。后续服装以已固定的人体与骨架转移权重，再人工修正并做动作测试。
5. 先测抬臂、弯肘、握工具、弯腰、深蹲、迈大步和转身，再测挥锄／浇水。重点看腋下、腰带、裆部、膝盖与裤脚。
6. 若目标骨架需要变更，遵守 §4.3 的版本规则并重验全部件；本轮仅建立步骤，不变更骨架或 UE 内容。
