## 1. 两道关：硬门禁 → 评分项

```text
提交 ──→ ①硬门禁（任一失败即不通过，不评分）──→ ②评分项（0/1/2）──→ 批准
             ↓ 失败                                    ↓ 有 0 分
           返工                                       返工
                                                      ↓ 有 1 分
                                           列负责人＋关闭日期，可条件通过
```

## 2. 硬门禁（任一失败，不得进入量产）

### 2.1 空间与比例

- [ ] 相机参数已记录且未再频繁变化
- [ ] 角色与建筑、门洞、台阶比例可信（[相机合同 §6](01-相机与空间合同.md)）
- [ ] 资产按**真实尺寸**建模，导入后在编辑器里量过
- [ ] 角色走到屋顶、树冠后面时**会淡出**，淡出不闪、不关碰撞
- [ ] 角色脚底不漂浮，阴影方向正确
- [ ] 可走区与交互物没有被朝北落差挡住（[相机合同 §8.1](01-相机与空间合同.md)）

### 2.2 风格

- [ ] 角色与场景看起来是**同一幅画**（不像写实模型走进插画）
- [ ] 交互物与成熟作物在正常画面可读
- [ ] 夜晚**不是**只靠整体压暗
- [ ] 季节**不是**只靠全屏换色
- [ ] 关闭全部后期层后，底层资产仍属于同一风格

### 2.3 技术

- [ ] Masked 边缘在目标 AA 方案下无不可接受的闪烁/噪点
- [ ] 不需要依靠**未记录的手工导入操作**才能正确显示
- [ ] 地表与状态层分离（翻耕、浇水、积雪**没有**画进基础地面）
- [ ] 会挡住角色的件用了带淡出通道的母材质
- [ ] 面数、贴图密度在 [相机合同 §5](01-相机与空间合同.md) 与 [性能合同 §2](06-性能预算与技术合同.md) 之内

### 2.4 可维护

- [ ] 源文件可重建，不是只有最终 PNG
- [ ] 资产卡填完，命名通过检查
- [ ] 上一批次 DoD 已全部关闭

## 3. 评分项

每项 **0 / 1 / 2**：0 = 不通过，1 = 需修改，2 = 通过。

| 项目 | 检查重点 |
|---|---|
| 轮廓 | 角色、入口、树、作物第一眼可读 |
| 比例 | 人、门、工具、作物、道路相互可信 |
| 机位 | 在游戏机位（标准档）下验过，不只是转台好看 |
| 色彩 | 冷暖、饱和度、明度层级统一 |
| 画意 | 贴图画法与主角四件道具一致；角色与场景不冲突 |
| 细节 | 地面安静，焦点区域有控制地丰富（70/25/5） |
| 接地 | 脚底、建筑、树、作物不漂浮 |
| 遮挡 | 淡出及时、稳定，被遮区域不影响操作 |
| 动态 | 日夜、季节、湿润、作物状态成立 |
| UI | 对话立绘与世界角色身份一致 |
| 技术 | Mip、LOD、碰撞、性能无明显缺陷 |
| 可维护 | 源文件、参数、命名、重导入流程完整 |

**通过条件**：硬门禁全过 **且** 评分项无 0 分。
**1 分项必须列出负责人和关闭日期**，否则算 0 分。

## 4. 必须提交的截图证据

同框截图是唯一有效证据，**转台、单件渲染、PSD 截图都不算**。

### 4.1 场景件

| # | 截图 |
|---|---|
| 1 | 目标镜头下与既有资产同框 |
| 2 | 角色站在它前面 |
| 3 | 角色站在它后面（验淡出） |
| 4 | 夜晚 |

### 4.2 角色件（6 种，缺一不可）

面向镜头 · 背对镜头 · 建筑前后 · 树冠下 · 道路与草地交界 · 白天与夜晚

## 5. 批次 DoD 机制

每个批次开工前先写 DoD，**写不出 DoD 的批次不许开工**。模板见 [模板/批次DoD模板.md](模板/批次DoD模板.md)。

DoD 必须包含：

1. 本批次要交什么（具体资产清单或画面）
2. 要关闭哪几个未确认问题（编号）
3. 要冻结哪几项
4. 通过判据（可勾选，不是"看起来不错"）

**失败回路**：任一批 DoD 未过 → 停下一批 → 修 → 重过。连续两轮不过 → 升级为待确认问题并指定关闭批次。

## 6. 隔天复看规则

自己做、自己批的评审（小团队常态），**必须隔一天再看一次截图才能签字**。

理由很实际：当天做完的东西，眼睛已经适应了它的缺陷。这条规则在长期项目里省下的返工，比任何工具都多。

## 7. 什么不算通过

明确列出来，因为这些说法在小团队里最容易被自己说服：

| 说法 | 为什么不算 |
|---|---|
| "导入成功了" | 导入成功不等于显示正确 |
| "没报错" | 没报错不等于符合规范 |
| "文件存在" | 存在不等于可用 |
| "工具跑完了" | 工具输出是数据，不是批准 |
| "截图看着挺好" | 截图不能证明性能、不能证明可维护性 |
| "先做着，后面统一改" | 这是返工的标准开场白 |
| "这件特殊，先破例" | 破例必须写进资产卡，否则下次重导入就丢了 |
