# 命名、目录与资产卡

> 编号：ART-STD-006 · 版本：1.0 · 更新：2026-09-20 · Owner：资产管理（会签：TA、程序）
> 类型：**流程规范**。
> 冻结等级：**冻结项 9**。
> 状态：本规范**从第一个正式生产批次（V08）起强制**。现存原型资产按 §5 沙盒条款处理。

---

## 1. 原则

1. **只用 ASCII。** 不用空格、中文、连字符以外的符号。
2. **版本后缀从 `_v001` 起。** 批准后改名必须在 [生产台账](../生产台账/00-首件与批次台账.md) 记录映射。
3. **目录区分用途，不靠改名区分。** Master 与运行时纹理靠目录分，不靠文件名加后缀。
4. **UE 内不在系统文件管理器改名。** 一律用编辑器重命名，走重定向与依赖检查。

---

## 2. UE 资产命名

### 2.1 格式

```text
<类型前缀>_<域>_<资产名>[_<部位>][_<通道或变体>][_v###]
```

### 2.2 类型前缀

| 前缀 | 类型 | 例 |
|---|---|---|
| `T_` | Texture | `T_Env_HouseA_Wall` |
| `SM_` | Static Mesh（Cards） | `SM_Env_HouseA_Wall` |
| `M_` | 母材质 | `M_Env_Card_Masked` |
| `MI_` | 材质实例 | `MI_Env_HouseA_Wall` |
| `FB_` | Paper2D Flipbook | `FB_Crop_Rice_Idle` |
| `SK_` | Skeletal Mesh | `SK_Chr_Player_UpperBody` |
| `SKEL_` | Skeleton | `SKEL_MR_Human_Base` |
| `PHYS_` | Physics Asset | `PHYS_Chr_Player` |
| `ABP_` | Animation Blueprint | `ABP_Chr_Player` |
| `AM_` / `AS_` | Montage / Sequence | `AM_Chr_Player_Hoe` |
| `CO_` | Mutable Customizable Object | `CO_Chr_Player` |
| `MM_` | Motion Matching 数据库 | `MM_Chr_Player_v001` |
| `BP_` | Blueprint | `BP_Env_CropPlot` |
| `L_` | Level | `L_Farmstead_v001` |
| `DT_` | Data Table | `DT_CropDefs` |
| `NS_` | Niagara System | `NS_FX_Rain` |

### 2.3 域（第二段，固定枚举）

| 域 | 含义 |
|---|---|
| `Env` | 场景（建筑、植被、地表、道具、远景） |
| `Chr` | 角色 |
| `Crop` | 作物 |
| `Ani` | 动物与岚兽 |
| `Por` | 对白立绘 |
| `UI` | 界面与图标 |
| `FX` | 特效 |
| `Sys` | 系统 / 通用 / 检查用 |

### 2.4 通道后缀（纹理）

| 后缀 | 含义 |
|---|---|
| `_BC` | BaseColor（默认，可省略） |
| `_M` | Mask / 数据（线性） |
| `_E` | Emissive |
| `_N` | Normal（本路线少用） |

### 2.5 材质参数前缀

| 前缀 | 含义 |
|---|---|
| `G_` | 全局时段（Tint、环境光补偿） |
| `S_` | 状态（湿润、积雪、遮挡偏置、季节权重） |
| `E_` | 自发光 |

### 2.6 例子

```text
T_Env_HouseA_Wall              建筑墙体贴图
T_Env_HouseA_Wall_M            对应遮罩（线性）
SM_Env_HouseA_Wall             对应 Cards 网格
MI_Env_HouseA_Wall             对应材质实例
T_Env_GroundGrass_Patch01      地表 Patch
T_Crop_Rice_S2                 水稻第 2 生长阶段
SK_Chr_Player_UpperBody        主角上衣部件
T_Por_Granny_Happy             阿婆开心表情立绘
M_Env_Card_Masked              环境卡片母材质（全项目共用）
```

## 3. UE 目录结构

```text
Content/MistRoost/
├─ _Sandbox/                原型与探针。禁止被正式关卡引用（见 §5）
├─ Art/
│  ├─ Common/               母材质、通用 Cards 网格、UV 检查图
│  ├─ Env/<AssetID>/        {Textures, Materials, Meshes}
│  ├─ Crop/<CropID>/
│  ├─ Ani/<AniID>/
│  └─ FX/
├─ Characters/
│  ├─ Base/                 SKEL_MR_Human_Base、角色母材质
│  └─ <CharID>/             {Meshes, Materials, Anim, Mutable}
├─ Portraits/<CharID>/
├─ UI/
├─ Data/
└─ Maps/
```

## 4. 源文件目录结构

```text
美术资产/
├─ 00-资产台账.md              全部 AssetID 的索引
├─ 场景/<AssetID>/
│  ├─ 01_Source/             PSD / KRA / Blend（Master）
│  ├─ 02_Export/             切片 PNG / TGA
│  ├─ 03_Preview/            同框截图、转台（命名带日期）
│  └─ 资产卡.md
├─ 人物/<CharID>/            同上
├─ 作物/ 动物/ 立绘/ UI/       同上
└─ _模板验证/                 PSD 母版与首件材料
```

源文件命名：

| 类型 | 格式 | 例 |
|---|---|---|
| PSD 母版 | `LookDev_<场景>_v###.psd` | `LookDev_Courtyard_v002.psd` |
| 切片导出 | `<AssetID>_<部位>_v###.png` | `HouseA_Wall_v001.png` |
| 角色源 | `<CharID>_<Part>_v###.blend\|fbx` | `Player_UpperBody_v001.fbx` |

## 5. 沙盒条款（现存原型资产怎么办）

现存这些路径是**验证期原型**，命名早于本规范：

| 路径 | 性质 |
|---|---|
| `Art/P2D_v001/` | **参考实现**，2D路线技术验证（见 [验证结论](../生产台账/01-P2D_v001验证结论.md)） |
| `Art/ArtLab/`、`Art/M0b/`、`Art/Placeholder/` | 早期探针 |
| `ArtValidation/LookDev_v002/` | v002 Paintover 回引擎试片 |

规则：

1. 这些资产**保持现名，不改名、不返工**——它们的价值是"证明技术可行"，不是"正式资产"。
2. 建议整体迁入 `Content/MistRoost/_Sandbox/`，保留原名。
3. **正式关卡（V08 起）一律不得引用 `_Sandbox/` 下任何资产。**
4. 从 V08 起新建的全部资产，**无例外**遵守 §2 / §3。
5. 若某个原型资产要转正，走"新建正式资产 + 复制内容"，不走改名。

已登记的**跨规范映射**（供查阅，不要求执行改名）：

| 原型名 | 对应正式命名 |
|---|---|
| `T_Ground` | `T_Env_GroundGrass_Patch01` |
| `T_House` | `T_Env_HouseA_Wall` |
| `T_TreeTrunk` / `T_TreeCrown` | `T_Env_TreeA_Trunk` / `T_Env_TreeA_Crown` |
| `T_Backdrop` / `T_BackdropStrip` | `T_Env_Backdrop_Mountain` |
| `T_SoilTilled` / `T_SoilWet` | `T_Env_Soil_Tilled_M` / `T_Env_Soil_Wet_M` |
| `T_CropStage0..2` | `T_Crop_<CropID>_S0..S2` |
| `M_T_Ground` 等 `M_T_*` | `MI_Env_*`（母材质统一为 `M_Env_Card_Masked`） |
| `SM_Mist2D_Quad` | `SM_Sys_Card_Unit` |
| `SM_Mist2D_QuadTilt40` | `SM_Sys_Card_Unit_Tilt40` |

> 早期原型里同时存在 `MI_MR_Probe_*`、`M_M0b_*`、`M_AL_*`、`MI_LookDev_v002_*`、`M_T_*` 五套命名。这正是"没有强制规范 + 没有沙盒隔离"的典型结果——本节就是为了不让它在正式内容里重演。

## 6. 资产卡（Manifest）

**每个 AssetID 一张卡，没有卡就不算完成。** 模板见 [模板/资产卡模板.md](模板/资产卡模板.md)。

必填字段：

| 字段 | 说明 |
|---|---|
| AssetID / 名称 | 与 §2 命名一致 |
| 资产分类 | 见 [2D场景管线 §2](02-2D场景资产管线.md) |
| Owner / 日期 / 版本 | |
| 源路径 | Master 文件 |
| 导出预设版本 | 哪一版切片/导入预设 |
| 世界尺寸 / 贴图尺寸 / 像素密度 | |
| 绘制视角 | 正俯视 / 画面所见 |
| Pivot | |
| 碰撞代理 | 形状、尺寸、前缘外扩量 |
| 遮挡偏置 K | 有/无，数值 |
| 交互锚点 | 命名 + 位置 |
| 状态层 / 季节变体 | 有哪些通道 |
| 授权 | 自绘 / 已购 / CC0 / AI辅助（含提示词与人工修改范围） |
| **偏离预设的手工操作** | **有就必须写，否则硬门禁判失败** |
| 批准状态 | `Prototype` / `Review` / `ApprovedForUse` / `Rejected` |

下游**只使用 `ApprovedForUse` 的版本**。

## 7. 交互锚点格式

锚点是美术与程序之间的接口，格式必须先定死：

```text
承载方式：Actor 上的场景组件挂点（Scene Component）
命名：ANCHOR_<用途>[_<序号>]
例：ANCHOR_Door、ANCHOR_Water_01、ANCHOR_Harvest
```

- 美术负责摆位置与命名，程序负责按命名表查询。
- **命名表是共同资产**：新增锚点类型必须双方会签，不许单方面加。
- 接口未就绪时，美术可用假数据先行，但**资产卡必须注明"待接真接口"**，不得当作完成。

## 8. 版本控制与备份

| 内容 | 位置 | 规则 |
|---|---|---|
| 文档 | Docs 仓库 | 正常 Git |
| UE 工程 | MistRoost 仓库 | 二进制资产**按唯一 Owner 串行编辑**，不做并行合并 |
| 美术源文件（PSD/Blend） | `美术资产/` | **不进文档 Git**；按批次打包备份 |
| 第三方原包 | `下载资产/` | 保留原始包与授权文件，**不得当成已验收资产** |

**回滚不是只回一个文件**：回滚一个资产要同时回它的材质、动画、骨架、数据引用和导入设置。资产卡里的"导出预设版本"就是为这件事存在的。
