## 0. 一页结论

| 东西 | 树干／茎 | 叶子 | 最后交付 |
|---|---|---|---|
| **乔木**（香樟、黄葛树、乌桕…） | **Blender Sapling Tree Gen 生成，原样使用**（§1A.3；0.x 时期是 Tripo 生模，已作废） | **大块树团**：负责人画 2×2 "整团树冠"图，脚本摆 8 个圆顶，材质从镜头方向投图（哆啦A梦牧场式，§1B） | **一个网格、三个材质槽**（树皮／树团／深绿内核） |
| **果树**（柿、枇杷…） | 同乔木 | 同乔木；另出一张**花期**叶鳞图 | 同乔木 **＋ 果实单独一个小网格**，挂在树上的挂点上（挂点在 §1A 流程里还没实现，§1A.7） |
| **果树树苗** | 当作物做（见 [作物生长阶段生成指南](10-作物生长阶段生成指南.md)） | — | 每阶段一个网格 |
| **灌木** | 没有树干，或几根短枝 | 同乔木 | 一个网格（多数只有叶片槽） |
| **竹丛** | 竹竿：AI 生模或 Blender 自制 | 竹叶簇插片 | 一个网格、两个材质槽 |
| **草** | **不用 AI**。Blender 脚本直接生成弯曲草叶条带（或用已购草丛包，见 §4.1） | — | 6–10 个草丛变体网格 |
| **花** | 草叶同上 | **花头**：生成 2D 花头贴图，贴在小插片上 | 几个花丛变体网格 |

**为什么叶子不生模：**
- AI 生模出来的树冠只有两种结果：要么是一坨"西兰花"团块，要么是一堆碎面噪点。
- 这两种都没法做风动，也没法做透光和按实例变色，面数还会超出 [预算](06-性能预算与技术合同.md)（乔木 8k–25k）。
- 沙盒里你认可的吉卜力风树（第三方包，仅沙盒），做法就是"实心树干 ＋ 叶簇插片"，业内风格化树也基本都这么做。

**为什么"单独生成"不等于"分两次独立生成整棵树"：** 树干和树冠必须对得上位。所以整棵树**只生成一次**，再由脚本拆成两份，见 §1.3。

### 1B.2 原理（为什么这样做）

- **树团是有体积的圆顶**：团与团之间有真实的前后遮挡，地上的影子是一团团的轮廓，不是一个圆球。
- **画从镜头方向投上去**：材质把圆顶上每个像素相对团中心的偏移，投到相机的右轴、上轴上去取图。所以树怎么转，玩家看到的都是这张画；锯齿轮廓由图的透明边切出来。团中心和半径存在网格的 UV1 / UV2 里（单位米）。
- **团与团分界是画出来的叶边，不是几何相交线**：
  - 每团的像素深度被压到"团中心往镜头前提一点"（Pixel Depth Offset），前后按团中心排；
  - 前面那团的锯齿叶边直接压在后面那团上，像颜料一层层叠上去。
  - 负责人 09-29 指出的"分界处太生硬"就是这样解决的。
- **明暗全在画里**：材质用 Unlit。受光材质配像素深度偏移，会被自己的影子盖黑；Unlit 仍然往地面投影。
- **深绿内核**：包在所有团中心外面，往后推 1.2 m，只从团缝里露出来，像参考图里团与团之间的暗部。

### 1A.3 树干（Sapling）

- 每个树种先出一批变体对比，负责人挑一个。香樟挑的是 D2。
- 参数以 `美术资产/树木/香樟/sapling_trunk.json` 为准，下表是香樟首件的值和用途。树干高度只用 `scale` 整体放大，形状不变。
- 树皮 UV 由脚本按真实尺寸展开：一张正方形树皮贴图对应 1 m × 1 m（`bark_tex_aspect: 1`，`bark_tile_m: 1.0`）。

| 参数 | 香樟 | 作用 |
|---|---|---|
| `levels` | 3 | 树干 → 主枝 → 小枝 |
| `scale` | 3.4 | 树干高度，米（09-29 从 3.0 放大，让树冠底抬高、树干露出三分之一以上） |
| `baseSize` | 0.65 | 下面这一段没有侧枝，也就是净干 |
| `segSplits[0]` ＋ `splitHeight` | 0.5 ＋ 0.5 | 在一半高度分叉成 3–5 根主枝。**不要用 `baseSplits`**：它固定在树干第一段就分叉，分叉会贴着地面 |
| `splitAngle[0]` / `curve[0]` | 32° / −20° | 主枝张开角度，以及先向外、再向上的弯曲 |
| `ratio` / `ratioPower` / `taper` | 0.075 / 0.85 / (0.55, 0.7, 0.85, 1) | 树干粗、主枝粗、末端只中等收细（风格化树干要短粗） |
| `bevelRes` | 2 | 截面 12 边 |

香樟 D2（`scale` 3.4）的结果：
- 树干高 4.27 m，约 3.1 m 处出现伸得最远的枝；
- 1664 个三角面。

### 1A.4 树冠（叶鳞）

树冠由三部分组成：
- **体积 = 主体蛋形 ＋ 鼓团**：
  - 主体蛋形轴线正对树干，上窄下宽，最宽处偏下，底部圆收。
  - 外面半埋两圈"鼓团"，都是独立的小圆顶：下圈 4 个、上圈 3 个，每圈方位均匀，上下两圈错开半格。
  - 珊瑚岛树冠一团一团的凹凸和明暗，就是靠鼓团做出来的。光滑的单个蛋形太规整，负责人 09-29 否掉了。
- **叶鳞**：每个圆顶各自从顶往下一排排铺。同一排绕一圈均匀排开，隔排错开半格。叶根贴表面，叶尖朝下、向外翘，上一排压住下一排，像屋瓦。
  - 被别的圆顶埋住的叶鳞不生成。
  - 圆顶交接处的叶鳞压暗成凹缝。
  - 叶鳞的位置、方位、角度、大小都带随机。
  - 主体顶上用 7 片小叶鳞围成一朵，至少往下斜 35°，不放大平叶。
- **深色内核**：每个圆顶一个，按圆顶中心缩到 62%（`core_scale`），只负责投影和一点点遮缝。负责人要求"宁可叶子稀一点，也不能从叶缝里露出大球"。

叶鳞的法线以所在圆顶的法线为主，混入 25% 的主体法线：每团有自己的受光，整棵树的受光又统一。

**不歪**：
- 鼓团方位是均匀分布的。
- 伸得最远的枝头会让上圈的一个鼓团正好落在它的方位上，把它包进去。
- 只有极少数情况下，某个枝头仍露在外面，才在它上面补一个小圆顶，同时在对面补一个一样的，保持左右平衡。

### 1.3 ② Tripo 与 ③ 拆分：为什么整棵只生一次

- **生一次：** 把①的图直接喂 Tripo。它会生成实心树干和团块树冠，这正是我们要的：团块就是树冠体积代理。
- **不要单独生成"枯枝树"再和树冠拼：** 两次独立生成对不上位。旧规则 01-树木 §4.4 也有同样结论。
- **拆分靠贴图颜色：**
  - Tripo 的烘焙贴图里，树干是褐色，树冠是绿色。
  - 脚本按每个面的平均色相把面分成两份。分界不干净的地方（绿色苔藓、褐色枯叶），在 Blender 里手动补刷几个面即可。
- **例外：** 如果 Tripo 给的主枝太粗、太短，或者被树冠吞掉、露不出来，就补生一张"同一棵树去掉全部叶子"的图，再生模只取树干。它和团块代理只按高度和包围盒对齐；枝条大多藏在叶子里，轻微错位看不出来。提示词（图生图，输入①）：

```text
把这棵树的叶子全部去掉，只保留树干和枝条。树干粗细、分叉位置、每根主枝的方向和长度与原图完全一致，
枝条末端自然变细。其余风格、颜色、视角、背景不变。
```

### 1.4 ④ 叶簇贴图（最影响风格的一张）

**要什么：**
- 一张正方形图集，2×2 四格。每格是一簇叶子（5–12 片叶，带一小段细枝），正面平视、平铺。
- 纯白底，我们抠图并扩边（防白边）。
- 不画方向光和投影：明暗由引擎的法线和光照给，贴图里只要固有色和笔触。
- 颜色取中间偏亮的绿：深浅变化由材质按高度和遮蔽统一加，贴图里压太深会发墨。

```text
【风格】（抄简报 §1.1 风格块）
【对象】游戏用的叶簇贴图图集：画面等分为 2×2 四格，每格正中一簇<香樟>的叶子，
每簇 5 到 12 片叶，带一小段细枝，叶片<卵形、边缘光滑、叶面有光泽>，四簇的形状和朝向各不相同。
叶子正面平视、平铺在画面上，不要透视，不要重叠到相邻格子。
颜色：明亮清爽的中绿到嫩绿，叶尖略暖，只有很淡的叶脉笔触；不要画阴影和高光方向，不要暗部。
【交付】纯白背景，每簇之间留足空白，不要地面、投影、文字、水印、边框；正方形，2048×2048。
```

负面词在简报 §1.4 的基础上加：

```text
透视、景深虚化、立体光影、投影、深绿墨绿、写实照片叶片、叶片互相遮叠成一片、格子线
```

**树种替换：** `<>` 里换成该树的叶形。黄葛树：椭圆、革质、有光泽。乌桕：菱状近心形、叶柄细长。柿：宽卵形、厚。枇杷：长倒卵形、粗叶脉、成簇轮生。

**季节变体：**
- 用上面那张图做图生图，只换颜色、不改形状，得到春（嫩黄绿）、秋（黄、橙、红）两张。
- 冬季不出图：叶片槽不显示，只剩树干。
- 形状不变，所以 UV 和插片全部复用，换季只换贴图参数（[管线 §7](02-3D场景资产管线.md)）。提示词：

```text
保持这张图集里每一簇叶子的形状、位置、大小完全不变，只把颜色改成<秋季：黄、橙、赭红混合，少量仍带绿>，风格与背景不变。
```

### 1.5 ⑤⑥ 装配与导出（脚本规格，供实现）

| 项 | 规则 |
|---|---|
| 插片数 | 乔木 150–400 片；插片边长 = 树冠直径 × 0.12–0.2 |
| 插片朝向 | 从代理表面向外，随机旋转；每片从 4 格里随机选一格 |
| 法线 | 从树冠代理（先平滑）传到插片：整团受光一致、边缘柔和，这是"吉卜力树"质感的关键 |
| 顶点色 | R = 在树冠里的相对高度，G = 离树冠中心的远近；给材质做上下渐变和风动权重 |
| 面数 | 树干 ≤ 6k，叶片 ≤ 15k（每片 2 个三角面）；LOD1/LOD2 按 50%/25% 减插片（[预算](06-性能预算与技术合同.md)） |
| Pivot 与尺寸 | 底部中心；按 [01-树木 §1](../../../美术资产/_提示词块/01-树木_v001.md) 的建议成株高缩放（Tripo 一律归一到 1 m） |
| 碰撞 | 只给树干一个胶囊体 |
| 命名 | `SM_Env_Tree_<树种>`；贴图 `T_Env_Tree_<树种>_Bark_BC`、`T_Env_Tree_<树种>_Leaf_BC`（含 alpha）；见 [命名规范](05-命名目录与资产卡.md) |

## 2. 果树

果树 ＝ 乔木 ＋ 三样东西：**果实、挂点、花期**。

### 2.1 果实：单独做，不烘进树

**原因：**
- 收获后果子要消失。
- 果子只在结果季出现。
- 数量会随天数变化：**每棵果树只挂三串果簇或三个果子，成熟后最多积攒三个**（负责人 09-28 定；积攒节奏由玩法定）。

烘进树冠就做不到这些。

**做法：**
- 生成一张单个果实的设计图（视角 B），用 Tripo 生模。
- 减面到 200–500 面，真实大小（柿子约 7 cm），底部 Pivot 放在果柄顶端。

```text
【对象】一个成熟的<柿子>，扁圆形，橙红色，顶部有四瓣深绿色宿萼和一小段果柄；单个，居中。
```

复杂一点的果实做"一串"（枇杷一串 5–8 个），做成一个网格。

### 2.2 挂点

- **每棵果树固定 3 个挂点**，插槽名 `Fruit_1`、`Fruit_2`、`Fruit_3`。果实（一串或一个）永远不合进树网格。
- 位置：树冠**中上部**外沿，水平相隔约 120°。游戏镜头是俯视，挂在树冠下半部的果会被树冠盖住（荔枝第一次试放时就是这样）。
- 一个挂点只放一串（或一个）果，所以果实要做得够大、够亮，一棵树 3 串也能被看见。荔枝果簇长约 40 cm。
- 运行时按"今天有几个果（0–3）"在插槽上显示果实实例。这一步由程序实现，见 §7。关卡摆放阶段先按"成熟、3 个全满"摆。
- **现在的做法（2026-09-28，荔枝）：** 组装脚本 `tree_trunk_assemble.py` 算出 3 个挂点写进 `MistRoost/Saved/trees/manifest.json`；导入脚本 `tree_trunk_import.py` 把它们建成网格插槽；沙盒摆场脚本读插槽，在每棵荔枝上摆 3 串 `SM_Fruit_T7F`（Actor `SKDress_Fruit`）。
- 已知：游戏镜头下一般看得到 2 串，第 3 串在树冠背面。

### 2.3 花期

- 春季开花：用叶簇图集做一张"叶＋花"的图生图，花朵只占三成左右。
- 桃、梨这种先花后叶的，单独出一张"只有花簇"的图集。

### 2.4 果树的生长

树苗到成树之间的几个阶段，按作物的方式做（每阶段一个小网格，见 [作物指南](10-作物生长阶段生成指南.md)）。

**成树的季节表现：**

| 季节 | 叶片槽 | 果实 |
|---|---|---|
| 春 | 花期图集 | — |
| 夏 | 夏叶 | 挂青果（可选） |
| 秋 | 秋叶 | 挂熟果（可收） |
| 冬 | 不显示 | — |

⚠ 游戏里还没有果树系统：作物表只能产出一种物品（`MistCropDef.h` 已注明"果树另开产出表"）。美术资产可以先按本节做好，系统另立需求。

## 3. 灌木与竹

- **灌木：**
  - 没有树干，或只有几根短枝。
  - 体积代理可以用 Tripo 生成的灌木团块，也可以在 Blender 里用几个变形的球拼出来。
  - 叶簇插片、法线传递同乔木。
  - 60–150 片插片，面数 1k–6k。
- **竹丛：**
  - 竹竿是细长圆柱加竹节，Tripo 或 Blender 自制都行。
  - 竹叶用"竹叶小枝"插片（细长披针形叶，3–6 片一组），只挂在竹竿上部三分之一。
  - 不按树干和树冠横切：见 01-树木 §4.2。

## 4. 草

**不用 AI 生图，也不用 AI 生模。** 草的质感来自四样：**成团直立的草丛形体**、**从根到尖的颜色渐变**、**整丛统一的柔和明暗**（法线做成半球形，不按单片叶子受光）、**风动**。这些都是几何和材质的事。

沙盒里草的来历（截至 2026-09-27）：
- 最早认可的 Painterly Grass 是非商用资源，**已从工程删除**（下载文件夹由负责人自行删除）。
- 之后临时用 SurvivalKit 的草卡（pd20–pd30）。
- pd31 起换成 **Anime Garden** 草丛包（负责人购买），做法与改动见 §4.1。

| 项 | 规则 |
|---|---|
| 生成 | Blender 脚本批量生成：每丛 8–30 根草叶，每根是 4–6 段、向外弯的窄条 |
| 变体 | 6–10 个：矮丛 45–70 cm、中丛、直立高丛 100–150 cm、芦苇状、贴地碎草 |
| 高度通道 | 相对高度（0 根 → 1 尖）：材质按它做根深尖亮的渐变，风也只推尖部。可以放顶点色 R，也可以放 UV1.x；沙盒原型用 **UV1.x = 高度、UV1.y = 离中轴距离**（导出脚本自动写） |
| 形状 | **以直立为主**。从 37.5° 俯视时，向四周摊开的放射状草丛会读成"星星"（沙盒实测） |
| 面数 | 每丛 100–400 三角面；Pivot 在底部中心 |
| 撒布 | 关卡里按材质层权重和噪声撒（沙盒脚本 `farmhillside_dress_sk_build.py` 已验证：分"铺底矮草 → 成团中草 → 边缘碎草 → 墙脚高草 → 水边芦苇 → 芒草带"几层；离路和田 3 m 内限高，挡镜头的位置不放高草） |

**可选的草叶贴图：** 想要叶边更"画"，可以生成一张"单根草叶笔触"图集，把条带改成带 alpha 的插片：

```text
【对象】游戏用的草叶笔触贴图：一排 8 根竖直的手绘草叶，每根是一笔从根到尖逐渐收细的水彩笔触，
长短、弯曲方向各不相同，根部颜色深、尖部亮；纯白背景，彼此不重叠，正方形 1024×1024。
```

### 4.1 沙盒 pd31–pd37：Anime Garden 草丛包怎么用、改了什么（09-28 起按 §4.2 收窄）

包的做法（看它的预览图和演示场景）：草丛不是一根根草叶，而是一簇簇**带 alpha 遮罩的笔触插片**，插片法线统一朝外，整丛读成一团柔和的色块；地面先铺一层矮草，再撒成团的中高草，花成片点缀。沙盒照这个思路铺。

| 项 | 包里原样 | 沙盒里改成 |
|---|---|---|
| 选用 | 草、花、灌木、水生植物、石头、玫瑰、绣球、向日葵等 | 只用草、野花、灌木、水生植物（约 55 个网格）；**不用它的石头**（负责人要求"不要碎石头"，溪边石统一用 `溪石中`；09-28 起石头可以用，见 §4.2），不用园艺花卉（玫瑰、绣球、向日葵不符合山野庄园） |
| 颜色 | 贴图自带的颜色，偏西式花园的饱和黄绿 | 只取贴图的 **alpha 遮罩**，颜色在材质里按高度重配：根深绿 → 中绿 → 受光黄绿 → 暖色 → 尖部浅色，再叠大尺度噪声和逐实例偏色；色值对齐 [色彩与光线设定](../设计方向/02-色彩与光线设定.md) 的上限 |
| 材质 | Blender 着色器（UE 里用不了） | 沙盒原型母材质 `M_AGD_Foliage`（见 §6），按"草／灌木／花头／图集花／树皮"五类出材质实例 |
| 明暗 | Blender 里的法线处理 | 导出时把法线改成半球形（莲叶类除外），整丛统一受光 |
| 尺寸 | 真实尺寸 | 保持真实尺寸；铺底 32–50 cm、成团 60–95 cm、墙脚高草到 1.5 m、灌木 0.8–1.5 m、少量大灌木 2–3 m |
| 水面 | — | 池塘放睡莲叶和两三朵睡莲，按吃水线贴水面；溪边放芦苇、梭鱼草、黄菖蒲、驴蹄草 |
| 地面 | — | 草丛缝里会露出关卡地面的草层。地面草层原本偏柠檬黄，和草丛一起读成"迷彩"。沙盒里把地面草层单独压暗、稍加蓝（只改沙盒的地形材质实例，正式地面未改）。注意：山石的苔色也取自地面颜色，地面调得太冷，山会一起发灰（pd36 踩过） |

调色的依据是渲染氛围图：暗部偏蓝绿、中间调偏橄榄黄绿、亮部发白不刺眼。沙盒迭代 pd31–pd37：pd31 整片柠檬绿、灌木发黑 → 压暗草、提亮灌木 → 地面单独调色，最后定在 pd37。

脚本：`MistRoost/Tools/animegarden_blender_export.py`（Blender 无头：挑网格、写高度通道、改法线、导出 FBX）、`animegarden_import.py`（导入 UE、建原型母材质和实例），撒布在 `farmhillside_dress_sk_build.py`。

⚠ **授权**：Anime Garden 的下载文件夹里带有转售站的标记文件。在找到正规购买凭证、确认许可允许商用之前，按"未核实第三方"处理：**只在沙盒**，不进正式关卡。确认后，正式的草、花、灌木可以直接用这个包（接正式的 `M_Env_Foliage`），不必再按本节自己生成。

### 4.2 2026-09-28 起：只留两种草，学 Coral Island 稀疏铺法

负责人："草太多了并不好看，你可以仿照 coral island 来搭建野外的场景……感觉就 3-4 种草就已经足够了……着重挑选 2 种草，将其改造为适配我们项目的美术风格，其他草不需要了。石头的话可以用的。"

| 项 | 现在的做法（沙盒 pd40；pd45 起草和灌木换成自制） |
|---|---|
| 草的种类 | 只留两种：**软簇草**（Tuft A/B/C）是日常草；**艾草丛**（Mug A/B/C）是第二种剪影，叶状、灰绿，只长在野地。**pd45 起两种都是自制**：`MistRoost/Tools/veg_own_build.py` 在 Blender 里程序生成（软簇草 = 70 根左右带弧度的几何草叶，每丛约 300 面；艾草 = 6–10 根茎上长羽裂叶，每丛 670–820 面），不用贴图，颜色全由色板按高度染；pd40 的 Anime Garden 改造版（`animegarden_grass_remake.py`）停用 |
| 形状要点 | 整丛要**直立、收拢**：草叶向外倒、叶尖下垂，从俯视镜头看会变成一颗颗"星星"或龙舌兰（pd44 踩过，和 pd31 的放射状草丛是同一个坑）。现在草叶根部倾角 6–8°、叶尖再弯 24–32°，整丛宽不超过约 0.5 m |
| 地面 | 草地主要由**手绘地面**撑起。草只长在交界处：路、田、院坝的边，墙脚，溪岸，树、石、灌木的脚下，野坡；开阔草地只在噪声斑块里放几小丛 |
| 数量 | 全图约 1.1 万丛（pd37 是十几万）；花压到 40 片小花丛 |
| 颜色 | 草身比地面**深一档、偏冷**，尖部亮而暖；只有根部一小段混入地面颜色（通过地形 RVT）。和地面同色会整片消失（pd38 踩过） |
| 尺寸 | 高 40–70 cm；离路和田 2 m 内限高 50 cm；艾草 60–105 cm，不进玩法区。Anime Garden 插片草当时要横向放大 1.5–1.9 倍才像一团；自制草叶本身够宽，只放大 0.95–1.15 倍 |
| 影子 | 两种草都投影。小丛草落在地面上的那一点阴影，是它在俯视里能读出来的关键 |
| 石头 | 改用 Anime Garden 的低面数手绘石（Rock04–12），按"一大一至三小"成组摆在山脚、坡上、墙脚和草地里，下沉 20–35 %，材质用 `M_Env_Master3D` 实例，偏暖灰。溪岸和池边的小石仍然只用 `溪石中` |
| 灌木 | pd45 起自制：同一个脚本用负责人的叶片图集（L1 小卵叶团、L4 菱形疏叶、L2 椭圆大叶簇）在 1–4 个椭球团上撒叶片卡，下面几根枝干；五种：Round（院坝边修剪球）、WildA/B/C（野灌丛）、WildTall（树旁 2–3 m 高灌丛），每个 330–550 面。材质都是自建的 `M_Tree_Leaf` 实例 |
| 不用的 | Anime Garden 的草、灌木网格不再摆放。花、睡莲、石头还在用 Anime Garden，SurvivalKit 的松树、地形材质、云和水也还在，按负责人"其他来源的都不需要用了"逐步换掉 |
