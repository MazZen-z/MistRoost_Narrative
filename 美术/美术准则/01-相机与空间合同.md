## 1. 为什么这份合同排在所有美术规范前面

这是"3D角色 + 2D分层场景"路线的地基。本路线不靠屏幕Y排序作弊，靠的是**真实世界坐标 + 固定相机 + 深度写入**。相机一变，下面全部连锁失效：

- 卡片的倾角（卡片必须与像平面平行）；
- 每张贴图该做多少像素（像素密度）；
- 卡片要做多高才和3D角色"看起来一样高"（§3.3 高度换算）；
- 角色走到树后面时头会不会穿帮（§5.3 遮挡偏置）。

**所以：相机不是"先随便摆一个"，相机是合同。**

## 3. 比例与高度换算

### 3.1 三种朝向，三种规则

| 物体类型 | 世界朝向 | 屏幕纵向占比 | 说明 |
|---|---|---|---|
| **3D角色**（真实立体） | 竖直 | `H × 0.766` | 被相机俯角压缩 |
| **立卡片**（Pitch −40°） | 与像平面平行 | `h × 1.000` | **不被压缩** |
| **地面卡片**（Pitch −90°） | 水平 | `d × 0.643` | 深度方向强压缩 |

### 3.2 角色屏幕高度基准

以 **170 cm** 角色为基准（最终身高待 V04 锁定）：

- 屏幕纵向世界占比 = 170 × 0.766 = **130.2 cm**
- 屏幕像素高度 = 130.2 × 1.371 = **≈ 179 px**（1080p 画面的 **16.5%**）

> **AD 提示（必须在 V04 主动确认，不要默认接受）**：179 px / 16.5% 属于俯视生活模拟的合理区间，但偏小的一侧。若首件看下来角色"太小、脸读不清、劳动动作没有存在感"，**唯一该动的旋钮是 Ortho Width**，不是角色身高、不是相机高度。
> Ortho Width 一动，§2 全部派生量、验证庭院尺寸（14 m × 8 m）、§4 像素密度档全部连锁重算——这就是为什么它是冻结项。参考换算：Ortho Width 1200 → 角色 209 px（19.3%）；1000 → 250 px（23.2%）。

### 3.3 卡片高度换算（本路线最容易做错的一条）

卡片与像平面平行，**不受俯角压缩**；3D角色受压缩。所以：

> **要让一个卡片物体看起来和身高 H 的3D角色等高，卡片的世界高度必须是 `H × 0.766`，不是 H。**

按字面高度建卡片，画面里的树和房子会**整体偏高约 30%**，人会显得矮一截。

| 目标观感高度 | 卡片世界高度 | 卡片屏幕像素高 |
|---|---|---|
| 与 170 cm 角色等高 | 130 cm | 179 px |
| 一层民房檐口 ≈ 270 cm | 207 cm | 284 px |
| 成年乔木 ≈ 600 cm | 460 cm | 630 px |

**碰撞代理使用真实世界高度（不乘 0.766）**——碰撞属于物理空间，视觉卡片属于投影空间，两者本来就不是一回事。

## 4. 像素密度与纹理尺寸

### 4.1 基准

| 用途 | Master 密度 | 运行时密度 | 理由 |
|---|---|---|---|
| 立卡片（建筑、树、道具） | **200 px/m** | **137 px/m** | 运行时贴近 1:1 texel:pixel |
| 地表 Patch | 200 px/m | 137 px/m | 深度方向天然 1.55× 过采样，不另外补 |
| 远景板（山、天空） | 100 px/m | 68–137 px/m | 弱对比、可低密度 |
| 立绘 / UI / 图标 | 不适用世界 px/m | 按 UI 实际显示尺寸 | 见 [立绘与UI管线](04-立绘与UI资产管线.md) |

### 4.2 为什么运行时压到 137 而不是直接用 200

固定正交相机是本路线最大的技术红利：**texel 和 pixel 可以做到接近 1:1**。1:1 时 Masked 边缘几乎不闪烁、笔触不糊、不需要靠 AA 救。

- **Master 留 200 px/m**：为将来开放缩放、改 Ortho Width 或出更高分辨率留重导出余地。
- **运行时贴图压到 137 px/m**：保住 1:1。
- 若 V03 决定开放缩放到最近档，再按最近档密度重导出运行贴图，**Master 不重画**。

### 4.3 常用尺寸档

按 137 px/m 换算，**世界尺寸决定贴图尺寸，不要反过来**：

| 卡片世界宽度 | 贴图宽度（运行时） | 常用档 |
|---|---|---|
| 1 m | 137 px | 256 |
| 2 m | 274 px | 512（含留边） |
| 4 m | 548 px | 512 或 1024 |
| 8 m | 1097 px | 1024 |
| 15 m（地表 Patch 上限） | 2056 px | **2048（硬上限）** |

- 地表 Patch 单块贴图边长 **不超过 2048**，超过就切块（见 [2D场景资产管线 §3.2](02-2D场景资产管线.md)）。
- 贴图尺寸取 2 的幂以保证压缩与 Mip；不足部分用透明留边，**不要拉伸内容去凑尺寸**。

## 5. 空间规则：Pivot、排序、遮挡、碰撞

### 5.1 摆放规则

| 资产 | Rotation | Pivot |
|---|---|---|
| 立卡片（建筑、树干、树冠、道具、作物） | Pitch **−40°** | 底部接地中心 |
| 地面 / 地表 Patch / 接触阴影 / 目标格 | Pitch **−90°** | 块中心 |
| 前景遮挡（屋檐、树冠、矮墙） | Pitch **−40°** | 与其装配父件一致 |
| 碰撞代理 | Rotation **0°** | 与视觉件同 XY，Z 按真实高度 |

- 作物：所有生长阶段 Pivot 一致（根部中心）。
- 动物：Pivot 在双脚/身体投影中心，所有动作帧一致。
- 树冠 Pivot 与树干装配点一致，**不许目测偏移**。

### 5.2 排序原则

1. 角色**保留真实世界坐标与高度**。永远不为了排序去改角色 Z。
2. 2D 环境使用 **Unlit + Masked**：颜色稳定、**写入深度**，遮挡由真实空间关系产生。
3. 只有必须半透明的内容才用 Translucent，且**逐个登记**（见 [性能预算](06-性能预算与技术合同.md)）。
4. 立卡片与像平面平行 ⇒ **整张卡片是同一个视深度**，卡片之间天然按 Pivot 深度正确排序。

### 5.3 遮挡偏置 K（必须写进每张遮挡卡片的资产卡）

**问题**：角色头顶在视深度上比脚底**近** `H × sin40° = H × 0.643`。170 cm 角色 ≈ **109 cm**。
所以角色站在树干卡片后面 50 cm 时，脚被挡住，**头却比树干更近，会从树干前面穿出来**。

**解法（契约化，不靠逐件手调）**：

```text
遮挡偏置 K = 角色身高 × sin(相机Pitch) = 170 × 0.643 ≈ 110 cm
```

- 所有**可被角色走到背后**的卡片（树干、建筑、矮墙、桥墩），材质开启 **Pixel Depth Offset**，向相机方向偏移 **K = 110 cm**。
- **配套硬约束**：该卡片的碰撞代理，前缘（朝相机一侧）必须比视觉卡片**外扩 ≥ K**。否则角色能站进偏置区里，会被错误遮挡。
- 纯前景遮挡件（屋檐、树冠、桥洞）角色永远在其后方，**不需要偏置**，按真实深度即可。

| 卡片类别 | PDO 偏置 | 碰撞前缘外扩 |
|---|---|---|
| 角色可绕到背后（树干、墙体、矮墙） | **110 cm** | **≥ 110 cm** |
| 纯前景遮挡（树冠、屋檐、桥洞） | 0 | 视需要（可无碰撞） |
| 地面、接触阴影、目标格 | 0 | 无 |

> 角色身高在 V04 锁定后，K 随之定稿；改身高 = 改 K = 改全部遮挡卡片的碰撞代理。这条必须写进 V04 的验收项。

### 5.4 共面 Z-Fighting

立卡片 Pivot 落在 Z=0，卡片底边与地面**恰好共面**，会沿接触线闪烁。

- 规则：立卡片 Pivot 统一抬高 **+1 cm**（或在母材质里给地面一个固定 Pixel Depth Offset）。
- 抬高量全项目统一，**不逐件调**；写进装配预设。

### 5.5 碰撞与交互

- 视觉面片 **≠** 碰撞。碰撞一律用独立简单代理（Box/Capsule）。
- 门、床、箱、井、作物有明确交互锚点；锚点格式见 [命名目录与资产卡](05-命名目录与资产卡.md)。
- 隐藏或淡出前景视觉时，**不得一并关闭必要碰撞与交互**。

## 6. 地面纹理：必须是"平面图"，不是"看到的样子"

这是从分层 PSD 转成可用资产时最常见的错误。

- 地面卡片是**水平**的，相机会自然把它压缩到 0.643。
- 如果直接把 A 画面里"已经被压缩过"的地面区域切出来当贴图，**就会压缩两次**，地面看起来又扁又短。

**规则**：

1. 地表基底、地表边界、状态层（翻耕/浇水/积雪）、接触阴影、目标格，**一律以正俯视（plan view）绘制**。
2. 从 Paintover 提取地面层时，**纵向反拉伸 1 ÷ 0.643 = 1.556×** 再存为 Master。
3. 立卡片相反：立卡片与像平面平行，**Paintover 里看到什么样，贴图就是什么样**，不做任何反变形。

| 层 | 绘制视角 | 从 Paintover 提取时 |
|---|---|---|
| 地面 / 地表边界 / 状态层 / 阴影 / 目标格 | 正俯视 | 纵向拉伸 **1.556×** |
| 建筑 / 树 / 道具 / 作物 / 前景 | 就是画面所见 | **不变形** |
| 远景板 | 就是画面所见 | 不变形 |
