## 1. 三层文档结构：先搞清楚该去哪个文件

新人读三分钟就该知道自己的问题归谁管。整个美术文档只有三层，**一层只回答一个问题**：

| 层 | 目录 | 回答的问题 | 改动频率 | 改了要做什么 |
|---|---|---|---|---|
| **设计方向** | [`设计方向/`](../设计方向/README.md) | **长什么样** — 风格支柱、色彩、地图、角色气质、概念与氛围图 | 低。改动=重做首件 | 走 §7 变量五步法 |
| **美术准则** | `美术准则/`（本册） | **怎么做** — 流程、规范、命名、预算、验收门禁 | 中。改动=改工作方式 | 改版本号＋通知全部在产批次 |
| **生产台账** | [`生产台账/`](../生产台账/README.md) | **做到哪了** — 谁在做、哪批过了、哪些问题没关 | 高。每批次都改 | 只记录，不定规则 |

**铁律：规则只写在准则里，数值只写在方向与合同里，进度只写在台账里。** 同一条信息出现在两个地方，就一定会有一份过期。历史上 33KB 的单文件把三层混在一起，这是它最大的问题（见 [README 拆分映射](../README.md)）。

## 3. 角色与批准权

一人可兼多职，但**批准权必须与执行权分离登记**——自己做的东西不能自己签"通过"，至少要有一次隔天复看并留下截图证据。

| 角色 | 做什么 | 对什么有唯一批准权 |
|---|---|---|
| 美术负责人（AD） | 风格、首件、验收 | 设计方向、首件模板、冻结项解冻 |
| 技术美术（TA） | 材质、导入预设、工具、预算 | 技术合同、导入预设、性能超标处置 |
| 场景/角色/立绘执行 | 按规格出资产 | 无（提交，不批准） |
| 程序 | 接口与数据驱动 | 接口格式 |
| 资产管理 | 台账、备份、授权 | 资产可用状态标记 |

**AI 协作者（含本项目中的 Claude Code）只做执行、检查与记录，不持有任何批准权**，详见 [协作外包与AI使用](08-协作外包与AI使用.md)。

## 4. DoR 与 DoD

### 4.1 DoR（可以开工）

一条都不能缺，缺了就是"还没想清楚就开始画"：

1. 有 AssetID、Owner、用途（哪个玩法/哪张图用）。
2. 有参考：设计方向里的哪一条支柱、哪张概念图。
3. 有规格：尺寸/像素密度/Pivot/碰撞需求/是否需要状态层与季节变体。
4. 镜头与比例依赖已锁（或明确标注"试样，不进正式地图"）。
5. 授权清楚：自绘 / 已购 / CC0 / AI辅助（记录提示词与人工修改范围）。
6. 有可用的测试场地（首件用验证庭院，量产用目标关卡）。

### 4.2 DoD（可以算完成）

| 维度 | 通过条件 |
|---|---|
| 审美 | 在目标镜头下与既有资产**同框**截图，符合设计方向 |
| 技术 | Pivot/碰撞/Alpha/Mip/排序/遮挡偏置全部按合同 |
| 接入 | 在 UE 实际关卡里显示正确，不依赖任何未记录的手工操作 |
| 玩法 | 相关交互（踩踏、采集、遮挡淡出）回归通过 |
| 性能 | 不使所在场景超出 [预算](06-性能预算与技术合同.md) |
| 可维护 | 源文件可重新导出；资产卡填完；命名通过检查 |

**"导入成功""没报错""文件存在"都不是 DoD。** 只有同框截图 + 资产卡齐全 = 完成。

## 5. 首件模板（Template）是什么

首件模板不是一张好看的概念图，也不是一个角色转台。它是**同一版本下制作、能互相校验的一组画面与源文件**。

### 5.1 三张主画面

| 画面 | 内容 | 验证什么 |
|---|---|---|
| **A 游戏主画面** | 同框：3D角色＋可行走地面＋道路边界＋建筑墙角门檐＋拆分树干树冠＋作物幼苗与成熟＋可交互道具＋一次"走到物体后面"的遮挡＋脚底接触阴影＋最小玩法提示 | 比例、轮廓、透视、接地、色彩、笔触、遮挡、玩法可读性 |
| **B 时段与季节** | 与 A **完全相同的相机和摆放**：中性白天 / 黄昏或夜晚 / 一个季节候选 | 变化来自可维护的参数、遮罩与替换层，不是全屏滤镜 |
| **C 对白界面** | 同一角色的：3D世界截图＋中立立绘＋两种表情＋真实对话框（姓名/正文/选项）＋16:9与一个窄画幅 | 立绘与3D角色的发型、肤色、服装语言、年龄感一致 |

### 5.2 拆解页（没有它，漂亮截图不算模板）

必须标注：相机参数 · 角色身高与屏幕像素高度 · 每个2D层的世界位置 · Pivot与接地点 · 碰撞代理 · 遮挡偏置 · 前景遮挡层 · 纹理尺寸与实际显示尺寸 · 日夜/季节/湿润遮罩 · 资产名称与版本 · 未解决问题。

模板见 [模板/首件验收表模板.md](模板/首件验收表模板.md)。

## 7. 变量五步法：美术方向要改的时候

长期项目一定会改方向。改法只有一种，反过来做就会毁掉已有资产：

1. **只改模板变量**——相机、角色比例、轮廓强度、色彩、细节密度、光照档位。一次只改一到两个。
2. 在验证庭院**重新输出 A / B / C 三张主画面**。
3. **列出受影响的资产类别**（不是资产清单，是类别：如"全部地表基底""全部树冠"）。
4. 跑**第二件复用测试**：不改母材质和基础规则，接入一件新资产。
5. 通过后才批准批量更新，并在 [生产台账](../生产台账/00-首件与批次台账.md) 记一行。

**禁止**：先改全部地图或全部角色，再从结果里总结新规范。那不是迭代，那是重做。

## 8. 评审节奏

小团队的评审要少而固定，否则要么不评审，要么天天开会：

| 节奏 | 做什么 | 证据 |
|---|---|---|
| 每件完成时 | Owner 自查 DoD 清单 | 同框截图存入 `03_Preview/` |
| 每批次末 | 首件/批次评审：硬门禁＋评分表 | 台账记一行，评分表存档 |
| 每两周 | 方向回看：对照设计方向**抽查已交付的3件资产** | 台账"回看"栏 |
| 每里程碑 | 冻结项复核：9项逐条确认没有被悄悄绕过 | 冻结项复核表 |

**隔天复看规则**：任何自己做自己批的评审，必须隔一天再看一次截图才能签字。当天觉得好看的东西，第二天经常不好看。

## 9. 失败回路

- 任一批次 DoD 未过 → **停下一批**，先修，再重过。
- 连续两轮不过 → 升级为 [待确认问题](../生产台账/00-首件与批次台账.md)，指定关闭批次，不允许"先做着看看"。
- 超预算 → 按 [性能预算](06-性能预算与技术合同.md) 的降级顺序处理：先降远景 → 地面 → 特效，**最后才动角色与交互物**。
- 与设计方向冲突 → 不自行降档成廉价方案，提出增员/外包/技术方案由负责人决策。
