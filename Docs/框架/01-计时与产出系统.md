# 框架 · 计时与产出系统（Timed Production）

> 相关：[运气系统](00-运气系统.md) · [种田](../玩法/02-种田.md) · [畜牧](../玩法/03-畜牧.md) · [技术架构与实现路线](02-技术架构与实现路线.md)

## 你的洞察（原话提炼）

> 作物成长、畜牧产出、加工器产出 —— 本质一样：**经过多少时间 → 得到多少产出**。需要一个**基类**。

**认同**，但我建议**再拆一层**：它们共享同一接口，但「所需时间如何累积」有两种模式，硬塞进「纯时长」会给浇水/季节等条件留下别扭的补丁。方案如下。

## 分两层设计

### 第一层：游戏时钟 `UGameClockSubsystem`（唯一时间源）
- 引擎侧只有一个权威时间源（`UWorldSubsystem` 或 `UGameInstanceSubsystem`）。
- 记录：`Year / Season / Day / Hour / Minute` + **`AbsoluteDay`（从开局单调递增的天数）** + `AbsoluteMinute`。
  > `AbsoluteDay/AbsoluteMinute` 是关键——用一个单调递增的整数当「时间戳」，一切时长计算都变成简单减法。
- 推进：可配置流速（如 1 现实秒 = N 游戏分钟）；菜单暂停；睡觉快进到次日清晨。
- 广播事件：`OnMinuteTick` / `OnHourChanged` / **`OnDayStarted`（最重要）** / `OnSeasonChanged` / `OnYearChanged`。
- **绝大多数产出挂在 `OnDayStarted`**（对标星露谷：作物在「过夜」时结算，而非实时生长）。

### 第二层：产出抽象 `UTimedProductionComponent`（基类 / 接口）
核心思想：**任意产出的状态 = f(现在时间 − 起始时间, 定义数据)**，可**惰性计算**，**不要每帧 Tick 成百上千个作物**。

两种求值策略（同一接口，内部分流）：

| 模式 | 适用 | 「所需时间」如何累积 | 求值时机 |
|---|---|---|---|
| **`Duration` 连续时长型** | 加工器（酿酒/腌菜/熔炉）、孵蛋、畜牧产奶周期 | 起始即定，`Start + Duration` 到点即成 | 惰性（交互/UI 查询时算）或 `OnDayStarted` 批量检查 |
| **`StagedDaily` 按天阶段型** | 作物 | **每天推进一阶**，但**需满足当日条件**（昨日已浇水、当前季节匹配）| `OnDayStarted` 逐日结算 |

> 差异只在于「所需时间」是**墙钟时长**还是**有条件的按天累积**。作物的浇水/季节因此是**一等公民**，不是补丁。

### 统一接口（示意）
```cpp
UENUM() enum class EProductionMode : uint8 { Duration, StagedDaily };

USTRUCT() struct FTimedProductionDef {          // 来自 DataTable / DataAsset（数据驱动）
    EProductionMode Mode;
    int32 DurationMinutes;      // Duration 模式
    TArray<int32> StageDays;    // StagedDaily 模式：各阶段所需天数
    bool  bNeedsWaterDaily;     // 作物
    TArray<FName> ValidSeasons; // 作物
    FName ProduceItemId;        // 产出物
    FIntPoint ProduceQtyRange;  // 数量区间 → 交给【运气系统】摇
    int32 RegrowDays;           // >0 表示可再生（收割后回到某阶段）
};

class UTimedProductionComponent : public UActorComponent {
    int64 StartAbsMinute;          // 或 StartAbsDay
    FTimedProductionDef Def;       // 引用行
    // 派生状态（可存档，也可由上面重算）
    int32 CurrentStage; bool bWateredToday; bool bDead;

    float GetProgress01(const FGameTime& Now) const;
    bool  IsReady(const FGameTime& Now) const;
    FYield CollectAndReArm();       // 返回产出；可再生则重置
    void  OnDayAdvanced(const FDateContext& Ctx); // 仅 StagedDaily 用：结算浇水/季节/推进
};
```

## 存档（顺带的好处）
- 状态可由 `StartAbs* + Def + 少量派生标志（阶段/是否浇水/是否枯死）` **确定性重算**。
- 存档只存这些原语；读档重算即可。**无需存整棵产出树**。
