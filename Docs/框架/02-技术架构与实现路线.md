## 一、模板现状（我读过源码后的结论）

当前工程 = **UE 俯视角（Top-Down）模板** + 两个变体（Strategy / TwinStick）。

| 项 | 现状 | 对种田游戏的意义 |
|---|---|---|
| `AMistRoostCharacter` | Character + SpringArm + 顶视相机 | ✅ 相机可直接用 |
| `AMistRoostPlayerController` | **点击移动**（NavMesh + `SimpleMoveToLocation`）+ Enhanced Input + 触屏 | ⚠️ **不适合种田**，见下 |
| `Variant_TwinStick` | **摇杆/WASD 直接移动** | 👍 可借鉴其移动代码 |
| 模块 | EnhancedInput / AIModule / NavigationSystem / StateTree / Niagara / UMG | 够用，暂不加新模块 |

### 关键决定 ①：移动方式改为「直接移动」
点击移动（Diablo 式）会和**精确的格子瞄准/工具使用**打架。种田游戏要的是
**WASD/左摇杆直接移动 + 朝向 + 对「面前格子」用工具**。
→ 建议把玩家改成**直接移动**（从 `Variant_TwinStick` 抄移动，保留顶视相机），
并加一个**朝向 / 交互目标**（面前格子或光标下格子）高亮。

## 二、基础架构（先立骨架）

- **数据驱动**：物品/作物/加工/掉落全用 `DataTable`（起步）→ 规模大再上 `DataRegistry`。
  - `FItemDef`（id/名/图标/堆叠/类型）、`FCropDef`、`FMachineDef`、`FLootTable`……
- **子系统（Subsystem）分层**：
  - `UGameClockSubsystem` —— 时间与 `OnDayStarted`（见 [计时](01-计时与产出系统.md)）
  - `ULuckSubsystem` —— 概率闸口（见 [运气](00-运气系统.md)）
  - `UFarmGridSubsystem` —— 格子坐标↔世界坐标，存每格状态（是否开垦/浇水/作物）
  - `UInventorySubsystem`（稍后）、`USaveSubsystem`（稍后）
- **格子与渲染解耦**：格子是逻辑数据；显示（翻土贴花、作物 Mesh/Sprite）是表现层，二者分开。
- **源码目录约定（已定）**：**新代码一律 `.h` 放 `Source/MistRoost/Public/<域>/`、`.cpp` 放 `Private/<域>/`**
  （如 `Public/Systems/`、`Private/Systems/`；后续 `Farming/`、`Data/` 同理）。
  头文件按**相对 Public** 引用：`#include "Systems/GameClockSubsystem.h"`；`MistRoost.h` 仍裸引用。
  `Public`/`Private` 由 UBT 自动识别，**不要**再往 `Build.cs` 加包含路径。模板原有文件保持原位不动。

## 三、分阶段路线（每阶段 = 可玩切片）

### Phase 0 · 地基 —— ✅ 已落地（2026-09-09）
- [x] `UGameClockSubsystem`（`Source/MistRoost/Systems/`）：`AbsoluteMinute` 权威时间 → 派生年/季/日/时/分；
  `Tick` 按 `MinutesPerStep` 推进；广播 `OnDayStarted / OnSeasonChanged / OnGameTimeChanged`；
  `SleepToNextMorning()` 过夜快进；屏幕左上角 Debug 显示日期时间。
- [x] `ULuckSubsystem`：`RollChance / RollQuantity / GetDailyLuck / GetEffectiveLuck`；
  每日 `RerollDailyLuck()`（由时钟在 `OnDayStarted` 调用）；**种子化** `(SaveSeed, AbsoluteDay, Purpose)` 可复现。
- [x] 新建 `Systems/` 目录并加入 `Build.cs` 的 `PublicIncludePaths`。
- [ ] 决定 Strategy/TwinStick 变体**保留为参考还是删除**（仍待你定）。

> **如何验证**：两个 Subsystem 均自动实例化，无需注册。
> 编译后 Play：左上角青色文字随时间前进；Output Log 打印 `OnDayStarted` 与 `DailyLuck`。
> 想立刻看到「过夜/天数推进」：在关卡蓝图取 `GameClockSubsystem` 调 `SleepToNextMorning`（Phase 1 接床/按键后自动）。
> 参数可调：`RealSecondsPerGameMinute`（默认 0.7）、`MinutesPerStep`（10）、`DaysPerSeason`（28）、`DayStartHour`（6）。

### Phase 1 · 移动与交互
- [x] **直接移动已落地（C++，2026-09-09）**：`AMistRoostCharacter` 改为 Enhanced Input 直接移动
  （`MoveAction` 2D 轴 → 相对相机 yaw 的 `AddMovementInput`），身体朝移动方向转（`bOrientRotationToMovement`）。
  `AMistRoostPlayerController` 精简，移除点击移动/NavMesh/Niagara 光标（保留鼠标光标供后续格子瞄准）。
- [ ] 计算「**目标格子**」（面前一格或光标命中格）+ 高亮 + 「使用工具」输入键（先打印日志）。**← 下一步**

> **需要你在编辑器接线（核心 C++、装配蓝图）**：
> 1. 新建 **Input Action `IA_Move`**，Value Type = **Axis2D (Vector2D)**。
> 2. 在 **IMC**（输入映射上下文）里给 `IA_Move` 加映射：
>    W/S → Y 轴（S 取负，用 Negate 修饰符），A/D → X 轴（A 取负），并加手柄左摇杆；对 WASD 各键用 **Swizzle/Negate** 得到正确的 2D 分量。
> 3. 在 **BP 角色**（继承 `AMistRoostCharacter`）的 Details 里，把 `DefaultMappingContext` 指到该 IMC、`MoveAction` 指到 `IA_Move`。
> 4. 旧的点击移动 IA/BP 控制器上的输入属性已无引用，可留可删。

## 四、可借鉴的开源参考（GitHub 调研结论）

> ⚠️ **诚实结论**：**没有**高质量的 UE5 星露谷类开源项目可直接抄。好的参考多在 Unity/Godot/Python，
> 但**种田逻辑与引擎无关**——学「架构与套路」，在 UE 里用 Subsystem + DataTable **原生重写**。

| 项目 | 技术栈 | 值得偷师的点 | 质量/说明 |
|---|---|---|---|
| [clear-code-projects/PyDew-Valley](https://github.com/clear-code-projects/PyDew-Valley) | Python/Pygame | **格子种田循环、日夜、天气、商人** 的最清晰实现 | ⭐ 教学向、极易读，逻辑参考首选 |
| [david2999999/Farming-RPG-Unity](https://github.com/david2999999/Farming-RPG-Unity) | Unity/C# | **作物生长、物品管理、存档（C# 接口+序列化）、时间系统** 全套 | C# 最接近 UE 心智；配套博客 [terresquall 系列](https://blog.terresquall.com/2021/10/creating-farming-rpg-in-unity-part-7/) 有架构讲解 |
| [xentripetal/ProjectVerse](https://github.com/xentripetal/ProjectVerse) | Unity/C# | **数据驱动、可模组化**的作物生命周期 | 参考「定义数据 vs 运行时」的拆法 |
| [UQdeco2800/farmsim](https://github.com/UQdeco2800/farmsim) | Java | **2.5D** 农场、得奖学生项目 | 结构参考，注意年代较早 |

其它可翻阅：[wkoziel/2D-Farming-Game](https://github.com/wkoziel/2D-Farming-Game)（Unity，背包/工具栏/商店）、[topics/farm-simulation-game](https://github.com/topics/farm-simulation-game)。
