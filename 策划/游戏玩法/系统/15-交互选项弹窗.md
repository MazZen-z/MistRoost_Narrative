## 1. 目标

- 【你已定】主角走近 NPC 出现弹窗：对话／交易，手里拿着礼物时加上送礼；做成通用 UMG。
- 【你已定】统一用鼠标左键点选项，走近就能点，不用先展开。
- 【建议】做成**通用的交互选项弹窗**：任何可交互物只要给出两个以上选项就用它（以后箱子"打开／搬起"、动物"抚摸／喂食"都能复用）；只有一个选项的（床）保持现在"按 E 直接执行"的手感，不弹窗。

## 2. 现状

- 【现状】[`UMistInteractionComponent`](../../../../MistRoost/Source/MistRoost/Public/Action/Interaction/MistInteractionComponent.h) 每 0.1 s 在主角身周做一次半径 200 cm 的球形重叠，挑出实现了 `IMistInteractable`、当前可交互、在正面、最近的一个，广播"聚焦目标变了"。数值在项目设置 `MistRoost - Interaction`。
- 【现状】游戏里一直显示鼠标光标（`AMistPlayerController::bStartWithMouseCursor`，键鼠瞄准要用），所以弹窗可以直接点。
- 【现状，阶段 B 起】[`AMistNpcCharacter`](../../../../MistRoost/Source/MistRoost/Public/AI/NPC/MistNpcCharacter.h) 的"对话"交给对话系统挑台词、开对话框（[16 篇](16-NPC对话.md)），仍广播 `OnInteracted` 给蓝图；NpcId 没填的 NPC 退回原来的交互（转身＋广播）。

弹窗**不改**找目标的逻辑，只在"找到之后"多一层选项。

## 3. 行为

| 状态 | 什么时候 | 显示 | 输入 |
|---|---|---|---|
| 隐藏 | 没有聚焦目标；或目标只有一个选项 | 单选项目标仍显示原来那一行提示文字 | 游戏输入 |
| **显示** | 聚焦到有两个以上选项的目标 | 在目标脚下**淡入**（0.2 s）一列选项 | **不抢输入**：照样走路、用工具；光标移到某项上它变亮，左键点它 |
| 离开 | 走开、换了目标、目标没了 | **淡出**（0.15 s），淡完清空；换了目标则在新目标脚下重新淡入 | 淡出途中点不到 |
| 让位 | 主菜单、轮盘、对话等面板打开；目标跑出屏幕 | 淡出，但不清空 | 面板关掉、目标回到屏幕后再淡入 |

- 点了**可用**的项 → 执行（对话＝打开对话框，阶段 B 已接上）。执行后若仍站在 NPC 旁边，弹窗留着：对话框打开时它让位淡出，对话结束后重新淡入。
- 点了**不可用**的项 → 不执行，在选项下方显示原因 2 秒（`ReasonDisplayTime`）；鼠标悬停在不可用的项上时也一直显示原因。
- 手位换了东西（例如切到一件礼物）→ 下一次扫描（0.1 s 内）"送礼"出现或消失；同一个 NPC 不重新淡入。

## 4. 选项数据

每个选项一个结构 `FMistInteractionOption`，只描述"这一项此刻的状态"：

| 字段 | 类型 | 说明 |
|---|---|---|
| OptionId | FName | `Talk`／`Gift`／`Trade`……执行时回传；也是选项表的行名 |
| Label | FText | 可空；填了就覆盖选项表里的名字 |
| bEnabled | bool | 不可用时仍显示（画淡），照常能悬停、能点，点了只显示原因 |
| DisabledReason | FText | 不可用的原因；空则用选项表里的默认原因。**总要有一句**（信息不只靠颜色，见 [游戏制作准则 §7](../../../../游戏制作准则.md) 可访问性） |
| Badge | FText | 名字后面的小字，如送礼的"1/2" |

- 显示顺序＝可交互物给出的顺序（NPC：对话、交易、送礼）。
- **名字、图标、默认原因是展示数据**，放在选项表 `DT_InteractionOptions`（行名＝OptionId；列：DisplayName、DefaultDisabledReason、Icon），界面经 `UMistInteractionOptionRegistry` 查，不写在代码和控件里（程序设计准则 §5）。表由 `MistRoost/Tools/data_tables_build.py` 首次建行，之后在编辑器里改。

`IMistInteractable` 加两个方法：

- `GetInteractionOptions(交互者, 输出选项列表)`：列出当前选项。
- `ExecuteInteractionOption(交互者, OptionId)`：执行某项。

**兼容旧交互物**：没实现这两个方法的（床）由交互组件按"一个选项＝原来的提示文字＋原来的 `Interact`"处理，行为与现在完全一样。

选项**每次扫描（0.1 s）都向目标重取一次**，没变化不广播、不重建按钮；所以手位、送礼次数、商店开关门这类变化不用另发事件。

## 5. NPC 的三个选项

| 选项 | 何时出现 | 可用条件 | 不可用时写 | 角标 | 执行 |
|---|---|---|---|---|---|
| 对话 | 一直 | NPC 可交互且不忙 | — | — | 开始对话，情境 `Talk`（[16 篇](16-NPC对话.md)） |
| 交易 | 一直【后续：NPC 身份表没配商店的不出】 | 营业条件成立 | 商店表里的打烊提示，如"打烊了（9:00–17:00）" | — | 打开交易界面（[18 篇](18-NPC背包与交易.md)） |
| 送礼 | **手位上是可以送的东西**：项目设置 `MistRoost - Item` 的 `NonGiftableItemTypes` 以外的类型（默认只排除工具）【后续：再加 NPC 身份表允许收礼】 | 今天／本周未送满 | "今天已经送过了"／"本周已送 2/2" | 本周剩余，如"1/2" | 直接送出手位上的那一件（[17 篇](17-好感度与送礼.md) §7），不弹礼物面板 |

- 阶段 A：交易、送礼先不可用（画淡），原因写"开发中"；D／E 做完后换成真实条件。
- 【实现，阶段 D，09-26】送礼已可用：点了直接送出手位那一件（17 篇 §7）。今天送过了画淡写"今天已经送过了"，本周送满画淡写"本周已送 2/2"；可送时角标写本周剩余（如"1/2"），生日当天写"生日"（文字都在项目设置 MistRoost - Relationship 的 Gift 分类，17 篇 §8）。没填 NpcId 的 NPC 画淡；身份表 `bCanReceiveGifts` 为否的 NPC 不出现这一项（上表"出现"一格的【后续】已做）。
- 选项的文字、顺序来自数据（选项表与 NPC），界面不写死几项。

## 6. 界面

**位置**：挂在目标**脚下**、左右居中。锚点是碰撞包围盒的底部，`AnchorHeightCm`＝0、`PopupAlignment`＝(0.5, 0)、`ScreenOffset`＝(0, 12)，都在 WBP 的细节面板里调；贴到屏幕边缘时往里收。

- 【注意】主角正对着 NPC 站时，选项会压在主角身上（珊瑚岛也是这样）。嫌挡的话把锚点挪到侧面即可，不用改代码。

**外观**：一列等宽的小胶囊（暖纸底、细描边，悬停转青绿），每项＝左侧鼠标左键图标＋名字。1080p 下字号 20、图标 22、胶囊高约 32、项间距 6。

- 不可用的项只把图标和文字画淡，底色不变：整颗半透明时背后的角色会透出来，字看不清。
- 原因显示在选项下方的小条里。
- 左键图标是 Slate 画的矢量（`WBP_MenuIcon` 的 `MouseLeft`），先占位；换美术时在 `WBP_InteractionOptionButton` 里换成 Image 即可。

**资产**（在 `/Game/MistRoost/UI/`，由 `MistRoost/Tools/common_ui_build.py` 首次搭建，之后在设计器里改外观）：

| 资产 | C++ 基类 | 用途 |
|---|---|---|
| `Interaction/WBP_InteractionPopup` | `UMistInteractionPopupWidget` | 弹窗；HUD 控件持有一份（`WBP_CloudHUD` 的 `InteractionPopupClass`） |
| `Interaction/WBP_InteractionOptionButton` | `UMistActionButton` | 一项 |
| `Styles/BP_InteractionOptionStyle` | `UCommonButtonStyle` | 胶囊的底色、描边、悬停与按下 |

旧的"激活态" `WBP_InteractionMenu`（`UMistInteractionMenuWidget`）已删除（09-25）。

**`WBP_InteractionPopup` 的控件合同**（控件名是约定，外观随便改）：

| 控件名 | 类型 | 必须 | 说明 |
|---|---|---|---|
| `PopupRoot` | 任意控件 | ✔ | 整个弹窗，**直接放在铺满全屏的 CanvasPanel 里**；位置由代码按目标投影设置 |
| `OptionContainer` | 面板 | ✔ | 放选项按钮（运行时生成，间距用属性 `OptionPadding` 调） |
| `ReasonText` | 文本 | | 不可用的原因 |
| `ReasonContainer` | 任意控件 | | 包住 `ReasonText` 的外框；没有原因时整体收起 |
| 属性 `OptionButtonClass` | 按钮类 | ✔ | 继承 `UMistActionButton`（默认 `WBP_InteractionOptionButton`） |

**动效**：淡入 0.2 s、淡出 0.15 s（属性 `FadeInTime`／`FadeOutTime`）。

**可换的资产**：胶囊底图、描边、图标、字体——全在 WBP 与样式资产里，C++ 不引用任何贴图。

## 7. 输入

| 操作 | 键鼠 | 手柄 |
|---|---|---|
| 点某一项 | 光标移到它上面，左键 | 【待定】 |
| 执行第一项（对话） | E、右键 | A |

- **左键冲突**：光标在选项上时，左键点选项；不在选项上时，左键照常用手位物（锄地等）。按下的这一下由选项按钮接住，不会同时传到游戏里；自动化测试核对过，按下时鼠标被按钮捕获，而不是游戏视口。
- 选项按钮**不拿键盘焦点**：点完之后 WASD、E 直接回到游戏。
- 不再有 W／S、方向键、数字键 1–9、Esc 这些弹窗专用键。数字键归快捷栏，方向键归背包翻页，弹窗不跟它们抢。
- **手柄**【待定】：现在只能用 A 对话，送礼、交易点不到。候选：
  - ① 摇杆驱动光标去点；
  - ② 对着 NPC 时方向键在选项间移动、A 确认（要和背包翻页商量）；
  - ③ 拿着礼物对 NPC 按 X＝送礼（星露谷做法，X 本来就是"用手位物"），交易另找入口。

  做交易（阶段 E）前定下来即可。

## 8. 与 CommonUI 的关系

- 弹窗是 HUD 层里的普通控件：不激活、不切输入模式（一直是 Game），不拿焦点；只有选项按钮本身接鼠标，弹窗铺满全屏的画布不挡点击。
- 选项打开的面板（对话、交易）推进 `UMistUIRoot` 的 ScreenStack，由 CommonUI 接管输入；面板开着时弹窗让位（淡出），关掉后恢复。**不自己调 `SetInputMode`**（沿用 `MistRoost/Tools/common_ui_handoff.md` 的约定）。

## 9. 边界情况

| 情况 | 处理 |
|---|---|
| 两个 NPC 挨着 | 沿用"正面＋最近"；聚焦换人时，弹窗在新 NPC 脚下重新淡入 |
| 按 Tab 开主菜单、按住轮盘键 | 弹窗淡出；关掉后淡入 |
| 睡觉淡出、读档、切关卡 | 目标没了 → 淡出并清掉目标引用（弱引用） |
| 淡出途中去点 | 点不到（淡出时不接点击），代码里再兜一次 |
| 弹窗显示时手位切到礼物、再切走 | "送礼"出现、再消失；前两项不动，不重新淡入 |
| 光标正好停在 NPC 脚下想锄地 | 会点到选项，挪开一点即可（与珊瑚岛相同）；嫌碍事就调锚点位置 |
| 键鼠与手柄切换 | 【待定】图标现在一直是鼠标；手柄方案定了再随设备换 |
| 目标在屏幕外 | 淡出 |
