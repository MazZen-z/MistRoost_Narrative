## 1. 目标

- 关掉游戏再打开，接着昨晚睡觉后的那个早上玩：钱、背包、NPC 的货、好感、记忆、旗标、日期、田地都在。
- 存档坏了（断电、写到一半）不丢档：退回上一份，并告诉玩家。
- 以后加系统、改结构，老存档能读：缺的块用默认值，认不出的 ID 按各篇的规则处理，不崩。

## 2. 现状（做之前）

- 【做之前】有一个存档**容器**（`UMistSaveGame`：存档头＋若干数据块）和 `UMistGameInstance` 上的存档／读档函数；只有玩家身份（名字、农场名）接了进去，也**没有地方调用**它们。各篇定好的存档块都只在内存里，重开游戏全部归零。
- 【现在】按本篇做完：13 个块接入，睡觉自动存，开游戏自动读。之后储物箱加了第 14 块 `Placement`（[21](21-交互物与容器.md) §6），主角属性加了第 15 块 `PlayerStats`（[22](22-主角属性.md) §12），制作加了第 16 块 `Crafting`（[25](25-制作.md) §5），技艺加了第 17 块 `Skills`（[24](24-技艺与经验.md) §4.5）。

## 3. 什么时候存、存在哪

| 时机 | 做什么 |
|---|---|
| 睡觉（含凌晨 2 点换天） | 时钟走到第二天早上、新一天的结算（作物长、出货箱结账、补货）都做完之后，自动存一次。所以存档里就是"新的一天的早上"。结算页、日历卡只是展示（[23](23-日终与换天.md) §2.2） |
| 开游戏 | 进到第一张图后，有存档就自动读；没有就是新游戏（换一个新的存档种子） |
| 调试 | `Mist.Save.Now` 随时存（§11）。白天调试存档再读，时间会回到存档那一刻，但位置仍放到床边 |

- 存档文件：`<项目>/Saved/SaveGames/MistRoost_Slot0.sav`；上一份：同目录 `MistRoost_Slot0_Backup.sav`。
- 项目设置里（`MistRoost - Save`）可以关掉自动读、自动存、上一份备份，改槽位名、提示显示几秒。
- 跑自动化测试时不会自动读档、不会写正式槽位（测试用自己的临时槽位，测完删掉）。启动参数 `-MistNoAutoLoad` 也能跳过自动读档。

## 4. 存什么：数据块

每个系统自己认领一块，按名字存；块内只存**稳定 ID**（物品 ID、NpcId、旗标名……）和数字，不存对象指针、不存场景里的 Actor。

| 块 | 版本 | 谁的 | 内容 | 定义在 |
|---|---|---|---|---|
| `Luck` | 1 | 运气 | 存档种子（按天固定的掷骰都用它，读档刷不出别的结果） | 本篇 |
| `Clock` | 1 | 时钟 | 当前时刻（绝对分钟） | 本篇 |
| `Wallet` | 1 | 钱包 | 金币 | 本篇 |
| `Inventory` | 2 | 背包 | 所有常驻容器（`Player`、各 `Npc.<NpcId>`、出货箱 `Shipping.Pending`、储物箱）：格数、每格的物品／数量／等级；手位 | 18 §12 |
| `Shops` | 1 | 商店 | 每家店上次上货的日子 | 18 §12 |
| `EconomyStats` | 1 | 经济统计 | 每件物品累计卖出、买入数 | 14 §10 |
| `Crafting` | 1 | 制作 | 开局以后学会的配方 ID（开局就会的不存，按配方表算；表里删掉的保留并警告） | 25 §5 |
| `Skills` | 1 | 技艺 | 每门技艺（按名字）的累计经验、已结算到第几级、上次结算以来涨的经验；最后结算的那一天。读档时等级不超过经验够得着的；认不出的技艺名丢掉并警告 | 24 §4.5 |
| `StoryFlags` | 1 | 旗标 | 已设的旗标 | 14 §10 |
| `NpcMemory` | 1 | NPC 记忆 | 每个 NPC 的记忆；还没传开的消息 | 14 §10 |
| `Dialogue` | 1 | 对话 | 每个 NPC 看过的条目及最后出现的日子 | 16 §15 |
| `Relationship` | 1 | 好感 | 每个 NPC 的好感、已结识、聊天／送礼记录、已知喜好 | 17 §11 |
| `FarmGrid` | 1 | 田 | 每块开垦过的地：土壤状态、今天浇没浇、作物 ID、阶段、在本阶段的天数、能不能收 | 09 |
| `Shipping` | 2 | 出货箱 | v2 起不写东西：箱里还没结算的东西在 `Inventory` 块的容器 `Shipping.Pending`。读到 v1 老块时把里面的东西搬进这个容器（删掉的、不能卖的丢掉并警告） | 21 §5 |
| `Placement` | 1 | 摆放物 | 玩家摆下的每个物件：编号、物品 ID、地图、格子、朝向、名字、颜色（箱子里的东西在 `Inventory` 块） | 21 §6 |
| `PlayerIdentity` | 1 | 玩家身份 | 玩家起的名字、农场名 | 本篇 |
| `PlayerStats` | 1 | 主角属性 | 当前生命、当前精力、当前岚息（09-28 加，按字段名存，老存档没有就保持新游戏的值）（上限、攻防等不存，由技艺、供奉、装备等来源读档时重新挂上）；读档顺序排最后 | 22 §12 |

存档头（不读全档就能看）：存档版本、农场名、游戏内日期、累计天数、现实时间、关卡名。

文件外面再包一层：标记 `MSAV`、文件格式版本、内容长度、校验和（CRC32），后面才是存档本体。

## 5. 不存什么

| 不存 | 为什么 |
|---|---|
| 玩家位置、朝向 | 永远在床边醒来；读档后把玩家放到床边 |
| 白天进行到一半的事（对话、交易界面、手里拿着的动作） | 只在睡觉时存 |
| NPC 站在哪、作物长什么样 | 由数据重建：NPC 按日程站位；田的网格按 `FarmGrid` 重画 |
| 消息管道、送礼的临时反应、头顶气泡、田的可视化 | 都是临时的，没有要跨天保留的东西 |
| 昨天的出货结算单 | 只给当天早上看，不跨存档（以后有了睡觉结算界面再议，见"决定与待定"） |

## 6. 读档的顺序

1. 读文件、校验（§7）。
2. **所有系统先回到新游戏的默认状态**（钱＝开局金币、背包＝开局物品、没有旗标……）。
3. 按固定顺序把存档里有的块写回去：运气 → 时钟 → 钱包 → 背包 → 商店 → 统计 → 旗标 → 记忆 → 对话 → 好感 → 田 → 出货箱 → 摆放物 → 玩家身份 → 主角属性。
   主角属性必须最后：当前生命、精力要等上限都算对了再写回，否则会被截断（22 篇 §12）。
   商店排在背包后面，因为"上次上货的日子"要看店的容器在不在：第 2 步会把 NPC 的包整个拿掉，存档里没有这个包，这家店就当没上过货，下次打开时重新上货（不会出现空店）。
4. **缺的块就保持第 2 步的默认值**（老存档、新加的系统都是这样）。
5. 通知界面刷新；田的网格整片重画；把玩家放到床边。

**读档不是新的一天**：不触发"新的一天开始"，所以不补货、不结算出货箱、不长作物、"今天第一次聊天"也不会再来一次。时钟只重算今天的运势（用存档种子，结果和存档前一样）。

## 7. 安全写入与损坏恢复

写：

1. 把所有块打包，先在内存里读一遍，确认能解开。
2. 写到临时文件 `…Slot0.sav.tmp`，再从磁盘读回来逐字节比对。
3. 把原来的主存档改名成 `…_Backup.sav`（上一份），再把临时文件改名成主存档。

任何一步失败：原来的主存档不动，屏幕提示"存档失败"，日志写原因。

读：

- 文件带校验和，写坏、截断、被改过都能认出来。
- 主存档坏了或不见了 → 读上一份，并在屏幕上提示"主存档损坏，已读取上一份存档（日期）"。
- 两份都坏 → 不读，屏幕提示；开游戏时就当新游戏，调试读档时保持当前状态不动；坏文件不删，留着排查。
- 存档版本比游戏新（降级了游戏）→ 拒绝读取并提示，不覆盖。

读档的结果只有四种（`EMistLoadResult`）：读到了、读到上一份、没有存档、失败。

## 8. 兼容规则（认不出的东西怎么办）

| 情况 | 处理 |
|---|---|
| 缺整块 | 默认值（§6） |
| 块的版本比游戏新 | 整个存档拒绝读取并提示 |
| 存档里有游戏不认识的块 | 原样保留，下次存档照样写回去（以后的版本加的块，回到老版本玩一下不会丢） |
| 物品 ID 已删除 | 背包里那一格变空，出货箱里那一堆丢掉，都写警告（18 §12） |
| 旗标、统计里的 ID 未知 | 保留，警告（14 §10） |
| 记忆里的 NPC 或消息名未知 | 丢弃，警告（14 §10） |
| 好感、对话里的 NPC 已删除 | 保留，警告（16 §15、17 §11） |
| 田里的作物 ID 已删除 | 作物去掉、地保留，警告 |
| 新加的 NPC、物品、店 | 没有记录＝默认值；新店第一次打开时按库存表上货 |

## 9. 背包组件

`UMistInventoryComponent`：挂在主角和 NPC 身上的"钥匙"。

- 只记一个名字：NPC 自动取 `Npc.<NpcId>`，主角是 `Player`。
- 要用的时候按名字去背包子系统找容器，**每次现找**，不缓存（读档后拿到的一定是最新的包）。
- 不建包、不改包、不存档。容器由背包子系统保管、由它存档；NPC 的包由商店建（18 §3.3）。没开店的 NPC 找不到包，返回空。
- 商店、交易界面、存档都**不依赖**这个组件：木匠不在场时 `Mist.Inv.Dump Npc.Carpenter` 照样能看（TC-TRADE-013 不受影响）。
- 临时模式（怪物偷东西、被打倒吐出来）以后做怪物时再加。

## 10. 程序结构

- `UMistSaveSubsystem`（`Core/Save`，GameInstance 子系统）：管各系统登记的块、写读文件、自动读档、提示。它不认识任何玩法系统。
- 每个系统在初始化时登记自己的块：块名、版本、顺序、"写出"和"读回"两个函数；读回收到"没有这块"时回到新游戏默认值。世界子系统（时钟、田、出货箱）在开始游戏时登记，世界销毁时注销。
- 块的内容是一个结构体，按字段名存（加字段、删字段、调字段顺序都不影响老存档）。
- `UMistGameInstance` 的存档函数只是转发给存档子系统，并负责填存档头里的日期；玩家身份由 `AMistPlayerState` 自己登记，并填存档头里的农场名。
- 睡觉：床在"睡到第二天"之后调自动存档；读档后床把玩家放到床边。顺序是：交互 → 画面淡到黑、主角不能动 → 过夜（作物、出货结算，弹结算面板）→ 自动存档 → 主角放到床边 → 淡回来。黑屏由床自己做，不用蓝图接。

加一个新系统的存档：写一个结构体 → 在系统初始化时登记 → 写"读回默认值"的分支 → 在本篇 §4 表里加一行 → 加一条往返测试。

## 13. 已知限制

- 只有一张图。换关卡时世界子系统（时钟、田、出货箱）会跟着旧世界销毁，现在没有带过去的办法；等有第二张图时一起做（开新图前先把世界块存进内存，新图开始时读回）。

- 存档不加密、不防改（单机游戏，不作为目标）。
