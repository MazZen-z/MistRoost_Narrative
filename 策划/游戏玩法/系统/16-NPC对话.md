## 1. 目标

- 【你已定】点"对话"后：立绘＋名字＋文本框，样式参考珊瑚岛截图（本地参考图 `概念设计/UI/珊瑚岛/人物对话.png`）；框线、名字牌等资产以后替换。
- 【你已定】每个 NPC 文本量大，要能随意扩展配置；有条件（节日、剧情过后、卖出某物之后……）；有通用的、有 NPC 专属的；注意本地化。
- 这套界面同时是美术台账 **V06 对白立绘**（"一名重要 NPC 三表情进实际 UI"）的验收载体，见 [生产台账](../../../美术/生产台账/00-首件与批次台账.md)。

## 2. 概念

| 概念 | 是什么 | 例 |
|---|---|---|
| 行 Line | 对话框里的一页 | "开春了，木料也跟着潮起来。" |
| 条目 Entry | 一次对话从头到尾（1～N 行，可带选项），**挑选的单位** | 木匠的"春季寒暄" |
| 情境 Trigger | 什么时候去挑条目 | `Talk`（点对话）、`Gift.Love`（收到最爱的礼物） |

| 优先级／权重 | 多条都满足时谁上 | 节日 500 高于季节 50 |
| 池 Pool | 几名 NPC 共用的一组条目 | 村民通用寒暄、店主通用招呼 |

## 3. NPC 身份表与立绘集（B0）

【现状】`AMistNpcCharacter` 自己存着 `NpcId`、`DisplayName`、`InteractionPrompt`，头文件注释写着"后续由 DT_NpcDefs 接管"。

`DT_NpcDefs`（行名＝NpcId，如 `Carpenter`，占位）：

| 字段 | 说明 |
|---|---|
| DisplayName | 显示名（FText） |
| Portraits | 立绘集 `DA_Por_<NpcId>`（软引用） |
| Dialogue | 专属对白：对话表 `DT_Dlg_<NpcId>`＋字符串表 `STR_Dlg_<NpcId>`（两个软引用；【实现】阶段 B 把原来的 DialogueTable 一列改成这一对） |
| Pools | 用哪些共享池，如 `Villager`、`Merchant` |
| Birthday | 季＋日，可空（[17 篇](17-好感度与送礼.md)） |
| bCanReceiveGifts／MaxHearts | 送礼与心数上限（17 篇） |
| ShopId | 可空（[18 篇](18-NPC背包与交易.md)） |
| TalkBlip | 文字音效与音高，可空 |

- 以身份表为准。Actor 上现有的显示名字段只作"没配表时的兜底"；两处都填了又不一致，体检警告（避免第二套真相，[AI必读 §3](../../../../AI必读.md#3-不制造第二套真相)）。
- 立绘集 `DA_Por_<NpcId>`（数据资产，美术直接拖贴图）：表情 → 贴图 `T_Por_<CharID>_<表情>`，另可放一张头像（人物页、名字牌用）。详见 §11。

**B0 实现（2026-09-25）**：`FMistNpcDef`、`UMistNpcRegistry`（`AI/NPC`，项目设置 `MistRoost - Npc` 的 `NpcTable`）、立绘集类 `UMistPortraitSet`。`AMistNpcCharacter` 的显示名改为先查表，查不到才用 Actor 上的；它的 `NpcId` 在编辑器里是下拉，只能从表里选；开场时 NpcId 不在表里、或 Actor 上的名字和表里不一致都会警告。`DT_NpcDefs` 先放两行占位 `Carpenter`（木匠）、`Granny`（阿婆），立绘、对话表、共享池在阶段 B 再填。立绘集：`DA_` 前缀已获批（[命名规范](../../../美术/美术准则/05-命名目录与资产卡.md) §2.2，v1.3）；阶段 B 建了 `DA_Por_Carpenter`、`DA_Por_Granny`（`/Game/MistRoost/Portraits/<CharID>/`），现在是空的，见 §11。

## 4. 编剧怎么写：一个 NPC 一张表

对话表在 UE 编辑器里编辑（§14）。一行＝一页台词或一个选项。**只在条目第一行（Seq＝1）填挑选信息**，续行留空——读起来像剧本。

| 列 | 必填 | 说明 |
|---|---|---|
| ConvId | ✔ | 条目 ID，同一条目的各行相同；ASCII，如 `Spring_01` |
| Seq | ✔ | 行序号 1、2、3……；**同一个 Seq 的多行＝一组选项** |
| Kind | | 空＝台词；`Choice`＝选项 |
| Trigger | 首行 ✔ | 情境，见 §7；续行留空 |
| Condition | | 条件列表（下拉，[14 篇](14-条件与世界事实.md) §2）。首行：条目条件；续行：本行条件（不成立就跳过这行）；选项：是否显示这个选项 |
| Priority | | 首行；默认 0 |
| Weight | | 首行；默认 1 |
| Chance | | 首行；0–1，默认 1。**每天抽一次，没抽中这条今天就不出现**——"打招呼时仍可能说本来的话"靠它 |
| Repeat | | 首行：`Always`（默认）／`OncePerSave`／`Cooldown:N`（N 天内不重复） |
| Speaker | | 空＝本 NPC；`Player`；`Narrator`（旁白）；或别的 NpcId（多人对话） |
| Expression | | 立绘表情，默认 `Neutral` |
| Emote | | 头顶气泡 ID（[19 篇](19-头顶UI与表情气泡.md)），可空 |
| Text | ✔ | 正文：绑定到字符串表 `STR_Dlg_<NpcId>` 里同名的一条（§14）；可用 `{PlayerName}` 等参数和 `<Name>…</>` 样式 |
| Note | | 给翻译、配音看的上下文（语气、知识边界、这句在回应什么）：写在字符串表那一条的 DevNotes 里 |
| Goto | 选项 ✔ | 选了之后跳到哪个条目 |
| Effects | | 效果列表（下拉），见 §9 |
| Gesture／VoiceCue | | 现在一律 `None`（剧情编写准则要求留字段） |

【实现】与上表的出入（都是为了表里只有一份真相）：

- **ConvId、Seq 不单独成列**，从行名读：行名写成 `<ConvId>.<Seq>`，选项在后面加小写字母（`Tea.2a`）。ConvId 只用字母、数字、下划线。
- Repeat 的 `Cooldown:N` 拆成两列：Repeat 选 `Cooldown`，天数填 CooldownDays。
- Speaker 选 `OtherNpc` 时，是谁填在 SpeakerNpcId（下拉）。
- Note 就是字符串表那一条的 DevNotes，数据表里没有这一列。
- Text 绑定到字符串表里与行名同名的那一条；不绑也行，运行时按"本表的字符串表＋行名"去取。直接在数据表里敲字，体检会提醒挪进字符串表。

**示例**（只演示格式，不是正式台词；Speaker、Weight、Gesture 等空列省略；条件和效果用简写，实际在下拉里配）：

## 5. 与剧情编写准则字段的对应

[剧情编写准则 §5](../../../剧情/剧情编写准则/00-剧情编写准则.md) 要求每行有九个字段，这里一个不少：

| 准则字段 | 本表 |
|---|---|
| LineID | 行名 `<ConvId>.<Seq>`（选项加字母，如 `Tea.2a`）；哪个 NPC 由所在的表决定（`DT_Dlg_<NpcId>`），合起来即 `<NpcId>.<ConvId>.<Seq>` |
| StringKey | 字符串表的 Key＝行名；本地化命名空间是字符串表的资产名（引擎默认，`STR_Dlg_<NpcId>`），各表 Key 重名也不冲突 |
| SpeakerID | Speaker（空＝本 NPC） |
| SourceText | Text |
| Context | Note（注意：不是本文的"情境 Trigger"） |
| Emotion | Expression（＋Emote） |
| Gesture | Gesture（现为 None） |
| VoiceCue | VoiceCue（现为 None） |
| BranchCondition | Condition |

## 6. 通用与专属

- **专属表** `DT_Dlg_<NpcId>`：这个人的台词。
- **共享池** `DT_Dlg_Pool_<PoolId>`：多人共用；身份表的 `Pools` 列出这个 NPC 用哪几个池。池里的行默认由"当前 NPC"说，文本里可用 `{NpcName}`。
- 挑选时专属条目和所属池的条目**放在一起比优先级**；想让专属台词盖过通用的，给它更高的优先级即可。
- 【建议】池按性格或身份分（温和的、粗犷的、店主……），不要只有一个"全员通用"大池：粗犷的木匠和温和的阿婆说同一句寒暄会出戏（剧情编写准则 §5：同一角色不能换人格）。

## 7. 挑选规则

**情境**（由代码触发，名单固定；新系统需要新情境时在这里补一行）：

| Trigger | 什么时候 | 说明 |
|---|---|---|
| `FirstMeet` | 还没结识时点"对话" | 找不到就退回 `Talk`；对话开始即记"已结识" |
| `Talk` | 每天第一次点"对话" | 主力台词；开始即记"今天聊过"（给好感，17 篇） |
| `TalkRepeat` | 同一天再点"对话" | 短句，如"还有事吗？"；不再加好感 |
| `Gift.Love`／`Gift.Like`／`Gift.Neutral`／`Gift.Hate` | 送礼之后 | 17 篇 |
| `Trade.Open`／`Trade.Buy`／`Trade.Sell`／`Trade.NoMoney`／`Trade.Refuse` | 交易界面里的小气泡 | 18 篇 |
| `Internal` | 只能被选项 `Goto` 跳到 | 永不参与挑选 |

**步骤**：

1. 候选：情境相符的条目（专属表＋所属池）。
2. 过滤：条目条件为真；重复规则允许（`OncePerSave` 没看过、`Cooldown` 已过）。
3. **概率**：`Chance` 小于 1 的条目各抽一次，没抽中的今天不参与。
4. 剩下的取**最高优先级**那一组，组内按权重抽一条。
5. 一条都没有：`FirstMeet` 退到 `Talk`，`Talk` 退到 `TalkRepeat`；还没有就用设置里的兜底条目（旁白"（对方点了点头。）"），开发构建日志警告"某 NPC 缺 Talk 台词"。
6. 记录：条目看过、条目最后出现的日子（冷却用）、今天聊过、已结识；条件里用到 `Heard(...)` 的，把对应记忆标为"已提过"（[14 篇](14-条件与世界事实.md) §5）。

**抽签按天固定**：第 3、4 步的随机数以"存档种子＋当天＋NpcId＋条目"为种子，同一天同一情况结果不变，读档刷不出别的台词；台词不受运气值加权。【实现】用运气系统在 B0 公开的 `GetDailyFixedRoll`：概率的键是"当天＋NpcId＋条目 Id"，组内按权重抽的键是"当天＋NpcId＋情境"。看过、冷却、概率都按"NpcId＋条目 Id"记——专属表和它用的池里有同名条目时这些记录会共用，体检会警告。

**优先级区间**（约定，不强制）：

| 区间 | 用途 |
|---|---|
| 1000 以上 | 首次见面；剧情强制【后续】 |
| 500 | 节日、生日 |
| 300 | 剧情过后（旗标） |
| 200 | 听说的事（`Heard`，一般配概率） |
| 100 | 心数台词 |
| 50 | 季节、星期、天气 |
| 0 | 通用 |

**防"霸屏"**：优先级 ≥100、`Always`、概率为 1 的条目，条件一旦成立就天天出现。体检对这种组合发警告，建议加 `Cooldown`、`OncePerSave` 或概率。条件里有 `Heard` 的不算——说过就消耗，不会天天出现。

## 8. 一次对话的流程

| 状态 | 做什么 | 输入 | 下一步 |
|---|---|---|---|
| 开场 | NPC 转向主角、主角转向 NPC；时钟加暂停原因"对话"；推对话面板 | — | 显示行 |
| 显示行 | 跳过条件不成立的行；**提交这一行的效果**；换立绘表情、播头顶气泡；打字机逐字显示 | 确认＝立刻显示全文 | 等待 |
| 等待 | 全文已显示，"继续"提示呼吸闪动 | 确认 | 下一行／选项／结束 |
| 选项 | 显示条件成立的选项 | 选、确认 | 提交选项效果 → 跳到 `Goto` 条目第一行 |
| 结束 | 关面板、去掉暂停原因、广播"对话结束" | — | 回到游戏；仍站在 NPC 旁边时弹窗重新淡入 |

- **效果在"这一行开始显示"时提交**，选项效果在确认时提交。所以中途关掉：看过的行效果都在，没看到的行不发生——不会丢，也不会白拿。
- 日常对话任何时候按 Esc／B 都直接结束；在选项处按 Esc 等于不选、直接结束。
- 选项组里一个成立的都没有＝数据错误：体检报出来，运行时直接结束对话。
- 剧情用的"不许中途关、只许快进"条目【后续】，届时由剧情系统加 `Locked` 标记。

【实现】

- 开场挑中的那一条，第一行不再判条件（挑的时候判过；开场已记"已结识"，再判会变）；选项跳到的条目，第一行和续行一样判，不成立就跳过。
- 同一时间只有一段对话；对话中再点"对话"不会开第二段。
- NPC 转身走 Mover 的"原地瞬移＋指定朝向"（只改 Actor 朝向会被 Mover 下一帧盖回去）；主角转身是把"松手后保持的朝向"改成朝着 NPC，由 Mover 按转身速度转过去。
- 时钟改成"暂停原因"集合，对话用 `Dialogue` 这个原因；以后菜单、过场各加各减，互不覆盖。
- NPC"忙"的标记还没做（日程系统来了再加）。
- 【阶段 C】"今天聊过"改在对话框出来之后才记：当天第一次聊天加的好感（17 篇 §3）要让名字牌上的爱心看得见地涨上去。"已结识"仍在开场之前记。

## 9. 效果（v1 只开放这些）

效果和条件一样：一个效果列表，每一项从下拉里选类型再填字段；程序上每种效果也是一个继承同一基类的结构体。

| 效果 | 字段 | 说明 |
|---|---|---|
| 设旗标 SetFlag | 旗标（从 `DT_StoryFlags` 里选） | 14 篇 §6.1 |
| 清旗标 ClearFlag | 旗标 | 只限声明为"可清"的旗标 |
| 加减好感 Affection | 点数（可负） | 对当前说话者；**对话带来的好感每人每天只结算第一次**，防反复刷 |
| 头顶气泡 Emote | 表情（从 `DT_Emotes` 里选） | 主要给选项用；台词行直接填 Emote 列 |
| 发物、扣物、给钱 | 【后续】 | 需要剧情编写准则 §4 的领奖事务 ID 与幂等设计，本轮不开放 |

【实现】设旗标、清旗标已做（`Narrative/Flags`，清旗标只认声明为可清的）；加减好感在阶段 C 做了（`Narrative/Relationship`，每人每天只结算第一次，可在项目设置 MistRoost - Relationship 关掉）；头顶气泡在阶段 D0 做了（`Narrative/Dialogue`，字段：表情、冒在谁头上——对话的 NPC／主角／另一位 NPC、时长覆盖）。台词行的 Emote 列也接上了：这一行开始显示时冒在说话的人头上；选项行和旁白写了 Emote 列体检会提醒（选项要冒气泡用这个效果），表里没有的表情也会报（[19 篇](19-头顶UI与表情气泡.md) §7）。占位台词里木匠的 `Help`（一颗心以后）答应帮忙 +15、阿婆的 `Hearts2_01`（两颗心以后）用上了"心数"条件。

## 10. 对话界面

## 11. 立绘

- 表情 ID 沿用 [立绘管线 §3](../../../美术/美术准则/04-立绘与UI资产管线.md)：`Neutral`／`Happy`／`Concerned`／`Sad`／`Angry`／`Surprised`；角色专属表情自己加。
- 每个 NPC 的表情数不一样（[3D 角色管线 §5](../../../美术/美术准则/03-3D角色与动画管线.md)：核心 NPC 6–8 种，重要 NPC 4 种核心表情）。体检检查"台词用到的表情在这个 NPC 的立绘集里存在"；缺了显示 `Neutral` 并列入体检，不崩。
- 所有表情同一画布、同一眼线（立绘管线 §2.2–§2.3）：界面对所有 NPC 用**同一套摆放参数**，换人换表情都不跳位。
- 【现状】占位立绘是全身像（如 [木匠立绘占位](../../../../美术资产/人物/NPC/立绘/木匠立绘占位.png)），界面按"眼线对齐＋底边裁切"只露上半身；正式立绘画布规范随 V06 定。
- 【实现】UE 5.8.2 导入不了 webp（引擎的图片格式里没有），所以两个立绘集现在是空的、界面不显示立绘，启动体检每个 NPC 报一条"立绘集还空着"。把占位图**另存为**真正的 PNG（文件名 `美术资产/人物/NPC/立绘/木匠立绘占位.png`）再跑一次 `MistRoost/Tools/dialogue_build.py`，就会导入成 `T_Por_Carpenter_Neutral` 并填进 `DA_Por_Carpenter`。（09-26：这个文件现在是把 webp 直接改了扩展名，内容仍是 WebP，脚本会跳过并提示；另外几张 4K 的 JPEG 是带背景的整幅画，不是抠好的人像。）缺的表情按表情汇总成一条警告，界面退回 Neutral。

## 12. 本地化合同

1. **文字全在字符串表**：Key＝LineID；**改措辞不换键**；删掉的行 Key 不复用（[游戏制作准则 §6](../../../../游戏制作准则.md)：ID 一经发布不复用）。
2. NPC 显示名在 `DT_NpcDefs`（FText）。
3. 参数只用命名占位：`{PlayerName}`、`{NpcName}`、`{ItemName}`、`{FarmName}`、`{Count}`；**不拼字符串**（事件与对话模板 C 节）。【实现】现在填 `{PlayerName}`、`{NpcName}`、`{ItemName}`；`{FarmName}` 在装配层，还没接。开局起名流程做出来以前，`{PlayerName}` 和主角的名字牌显示占位名"主角"（`AMistPlayerState` 的 PlaceholderName）——不能退回引擎默认的名字，单机时那是电脑名。
4. 主角性别是玩家自定义项（剧情编写准则 §1）：能不用第三人称代词就不用；非用不可时写 UE 文本格式自带的性别修饰，形如 `{PlayerGender}|gender(他,她,TA)`（引擎 `TextFormatter` 里有 `gender` 与 `plural` 修饰，已查源码确认）。数量用 `{Count}|plural(one=…,other=…)`，中文不需要，给译者用。
5. 富文本标签只许白名单：`<Name>`、`<Item>`、`<Place>`、`<Emph>`；体检检查源文本标签成对；译文保留标签是 LQA 检查项。【实现】白名单在项目设置 MistRoost - Dialogue 的 AllowedRichTextTags；体检还查不嵌套（RichTextBlock 不支持嵌套）。
6. 源语言：简体中文；对白单独一个本地化目标（Q4 已定）。
7. 字体：中文复合字体＋回退；缺字进 LQA（[游戏制作准则 §7](../../../../游戏制作准则.md) 本地化一行）。
8. 【未做】长度：一行＝一页，写作时按**实际对话框**控制在 3 行内（剧情编写准则 §5：不拿中文字数推断外语长度）；超长自动缩小字号到下限【占位】85%，还超出就在开发构建日志警告。伪本地化用引擎自带的 `LEET` 测试文化（非 Shipping 构建）。
9. 翻译上下文：Note 写在字符串表条目的 DevNotes 里（5.8 的字符串表 CSV 导入专门有 `DevNotes` 列，已查源码）；导出给译者时能否带上，接本地化流程时实测。

## 14. 在哪里写、谁为准（Q3，随 Q2 调整）

Q2 选了下拉，条件这类结构在 CSV 里没法手写，所以 Q3 调整为：**对白全部以 UE 编辑器里的资产为准**——正好回到你原来"编辑器数据为准、脚本只首次铺设"的原则。

| 内容 | 放在哪 | 在哪改 |
|---|---|---|
| 结构：条目、情境、条件、优先级、概率、效果、表情…… | 对话数据表 `DT_Dlg_<NpcId>`，行名＝LineID | UE 数据表编辑器 |
| 文字：正文、给翻译的说明 | 字符串表 `STR_Dlg_<NpcId>`，Key＝LineID | UE 字符串表编辑器；对话行的正文绑定到这一条，数据表编辑器里也看得到文字 |

**大量新写台词时**：

1. 编剧在表格里写：LineID、正文、说明。
2. **第一次建表**：用字符串表自带的"从 CSV 导入"（列名 `Key`、`SourceString`、`DevNotes`）。引擎的这个导入会**先清空整张表再导**（已查 5.8.2 源码），所以只用于第一次。
3. **之后追加**：用铺行工具（可重复运行的编辑器脚本，放 `MistRoost/Tools/`，遵守 [AI必读 §1](../../../../AI必读.md#1-脚本必须单独存放)）：只把字符串表里**还没有的 Key** 补进去，并在对话数据表里补同名的空壳行；**已有的文字和行一律不动**。
4. 在编辑器里给新行配情境、条件、概率等。

【实现】铺行工具是 `MistRoost/Tools/dialogue_build.py`：第一次铺设两名占位 NPC（木匠 14 个条目 20 行、阿婆 8 个条目 9 行）和温和村民池 `Villager`（3 个条目，阿婆用、木匠不用）、记忆规则 `DT_NpcMemoryRules`、立绘集，并把身份表的 Portraits、Dialogue、Pools 三列填上（只填还是默认值的列）；之后再跑只补缺的 Key 和行，已有的一律不动（实测第二遍 0 新增）。编剧表格追加：设环境变量 `MIST_DLG_SHEET=<CSV>`、`MIST_DLG_TARGET=<NpcId 或 Pool:<PoolId>>` 再跑，CSV 列 `Key`、`SourceString`、`DevNotes`；补的空壳行没配情境之前体检会停用它。池在项目设置 MistRoost - Dialogue 的 Pools 里登记（`Config/DefaultGame.ini`）。占位台词的 DevNotes 都带"【占位】"。

- 翻译走引擎的本地化导出；文字只在字符串表里，数据表不存文字。
- 文字不进数据表的原因：[程序设计准则 §9.2](../../../../MistRoost/程序设计准则.md#repo-scripts) 记过——FText 写进数据表后导出成 `NSLOCTEXT`，每次重写都让资产变脏、冲掉本地化 Key；放字符串表就没这个问题，Key 也读得懂。
